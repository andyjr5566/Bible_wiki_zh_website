# 經文搜尋「同一原文詞的其他譯法」：資料來源改版

狀態：試做中（2026-11-27 決定）。先用 MACULA 做目前上線的 6 卷（創世記～約書亞記），做完拿前後對照給使用者看，再決定要不要全面換。

## 這個功能要做到什麼

讀者查一個中文詞 → 找到它的原文字 → 看這個原文字在和合本還有哪些譯法 → 列出**原文是這個字、而且是這個意思**的經文。四段都要可靠，最後的經文才可信。

## 現在的資料為什麼會錯（2026-11-27 追查）

目前的 `quartz/data/verse-original-terms.json` 由 `scripts/build-verse-compat.py` + `scripts/verse-compat/audit.py` 產生，來源是 CrossWire 的 ChiUn 模組（資料來源欄：信望愛 FHL）。

- **信望愛的標法是「編號標在一段中文後面」**，編號涵蓋從上一個編號到這裡的全部文字，例如 `我做<H6213>這<H2088>事是心<H3824>正<H8537>`。中間沒有自己編號的字（「事」「是」「的時候」）會被併進下一個編號。信望愛目前線上 API 的資料還是這樣。
- **原文有、和合本沒譯出的字**，編號會被掛在旁邊的詞上，例如王上 11:4 `大衛<H1732><H9003><H3824>`（原文「像他父親大衛的心」，和合本沒譯「心」）。
- 我們的程式把「一個標記裡的整段中文」當成「這個原文字的譯法」，只去掉前後的「的、這、你」，而且一段掛多個編號時，整段算給每一個編號。結果：le.vav 的譯法裡出現「事是心」「時候心」「恐怕你心」「大衛」「終日」。
- **經文本身大多是對的**（原文確實有這個字），錯的是「哪幾個中文字是譯法」，以及因此被錯當成查詢入口的詞。
- 另一個獨立的問題：**只按原文字列經文，不分意思**。例如查「赦免」會連到 na.sa，把它出現的 180 處（大多是「舉、抬」）全列出來；查「獻祭」連到 qa.rav，列出 186 處「近前」。

全本約 56,000 筆對應中，約 17% 是單一編號但切出 3 字以上，約 12% 是一段掛多個編號（各有一部分其實是正確的長譯法或文法小詞）。

## 查過的資料來源（2026-11-27）

| 資料 | 結論 |
|---|---|
| 信望愛／CrossWire ChiUn（現用） | 標在一段文字後面，不是逐字對照 |
| OpenGNT 和合本欄、BibleMate tagged-bibles、OpenHebrewBible | 都建立在信望愛的切法上；BibleMate 實測錯更多；OpenHebrewBible 限非商業 |
| Clear Bible Alignments | 沒有中文（只有新約和合本人名） |
| Logos／Lexham《反向逐字對照和合本》 | 品質最好，但商業產品，不能取出 |
| 亞洲聖經協會（吳安迪 2010 論文）的和合本與原文對照 | 沒有公開；已擬信詢問 Clear Bible |
| **MACULA Hebrew／Greek**（Clear Bible／Biblica，CC BY 4.0） | **採用為主幹**：每個原文字有中文解釋（Cherith，吳安迪），希伯來文每處另有字義編號（SDBH） |

MACULA 在上面出錯的經文全部正確（創 20:5 le.vav→心；詩 13:2 yo.mam→終日、le.vav→心）。字義編號直接分開意思，例如 na.sa 第 6 義＝赦免、饒恕（26 處），qa.rav 第 1 義＝獻。

限制：中文解釋是現代簡體用語，不是和合本原字。舊約實詞中 71% 原字出現在那節和合本，13% 部分出現，16% 沒出現（例如 MACULA「穹苍」，和合本「空氣」）。

## 決定

| # | 決定 | 理由 |
|---|---|---|
| O-1 | 「這節有哪個原文字、是哪個意思」以 MACULA 為準；信望愛的標記只當「大概在哪一段」的定位線索。 | 信望愛不是逐字對照，修剪補丁治標不治本。 |
| O-2 | 每個原文字在和合本經文裡的對應字，依序用：①MACULA 中文解釋（轉繁體）在經文中原字出現，多處出現時用信望愛的位置挑；②同一原文字＋同一字義在其他節已確定的和合本譯法，在信望愛標的那一段裡找；③都找不到就標「和合本未直接譯出」（譯法留空），**不硬掛在旁邊的詞上**。AI 判讀只先抽樣評估能救回多少，不全面跑。 | 寧缺勿錯；先量出規則能做到哪裡。 |
| O-3 | 虛字（介系詞、連接詞、冠詞、受詞記號、代名詞字尾等）依 MACULA 詞性排除，不再自己列清單。 | 一個來源、規則可說明。 |
| O-4 | 每筆對應帶字義鍵 `H<編號>.<字義編號>`，之後「按意思列經文」直接用。 | 解決「赦免→180 處抬東西」。 |
| O-5 | 譯法必須是網站經文（1919 和合本）裡的原字子字串，標示才對得上。MACULA 是希伯來文分節，要對到和合本分節（STEP TAHOT 有兩套節號對照）。 | 創 31:55／32:1、出 8 章、利 6 章、民 16–17 章、申 13、23、29 章等分節不同。 |
| O-6 | 試做輸出放在暫存資料夾，不改 `quartz/data/`、外掛與網站；確認後才接上。 | 試做不影響正式站。 |
| O-7 | 延伸區**不丟長清單**：每個原文字（＋意思）一張卡，預設只放「你找到的一處＋另一種譯法的一處」兩節對照，完整經文清單收在按鈕後面。（2026-11-28 使用者同意） | 使用者：長清單沒有幫助。 |
| O-8 | **依出現次數排序**：卡片依「讀者輸入的詞翻這個意思的處數」排（同數再比該意思的總處數；2026-11-28 實測「時候」時改，原本依總處數會把只偶爾譯作「時候」的 yom「日、天」排第一）；卡片內的譯法標籤與條形比例依和合本各譯法的處數由多到少排；「另一種譯法」預設挑處數最多、且不含查詢詞的譯法。（2026-11-28 使用者提議） | 常見的譯法先看到，效果較好。 |
| O-9 | 展開條件：讀者輸入的關鍵字至少有 2 處被和合本拿來翻同一原文字、同一意思，才顯示那張卡（擋單筆對應錯誤）；不看比例。超常見字（kol、hayah、amar、ben、bo、asah、natan）不展開。 | 2026-11-27 檢討：A 門檻（≥3 次且 ≥15%）是自訂的，比例擋的是「多」不是「錯」，改由 O-7 的顯示方式處理。 |

## 上線第一版（2026-11-28 使用者看過樣稿同意）

範圍：目前上線的 6 卷（創世記～約書亞記）。資料格式與載入方式要能直接擴到全本（約 30 萬筆對應），不能一次下載全部。

### 資料（D）

1. **原始資料（進版控）**：`quartz/data/verse-original-terms.json` 改為 `version: 2`：
   - `lexicon`: `{ "H5375": [lemma, translit] }`（不再放自動產生的中文說明）。
   - `chapters`: `{ "<slug>": { "<verse>": [[sid, rendering, senseKey], …] } }`。`rendering` 可為 `""`（和合本未直接譯出）；`senseKey` 為 `H5375.6` 或沒有字義編號時 `H5375`。
   - `attribution`：MACULA、Cherith、STEP 的出處字串。
   - 由 `scripts/original-terms/build_original_terms.py` 產生。AI 判讀的採用結果另存成可進版控的小檔（例如 `scripts/original-terms/data/ai-decisions.jsonl`，以 occurrence id 為鍵），重建時不必再呼叫模型。
2. **網站輸出（emitter `quartz/plugins/emitters/verseIndex.ts` + `quartz/util/verseIndex.ts`）**，只收已上線章節：
   - `static/verseOriginal/index.json`（小）：
     - `senses`: `{ senseKey: [total, none, [[rendering, count], …]] }`（精簡 tuple）。`total` 是這個意思的總處數（含未直接譯出）、`none` 是未直接譯出的處數；`renderings` 含**全部**譯法，依處數由多到少、同處數依第一次出現順序。Strong 編號是字義鍵 `.` 之前的部分；意思標籤（前兩個譯法，例「赦免、饒恕」）由前端用前兩個譯法組。`entries` 每筆是 `{ slug, title, isHeadword }`（`isHeadword` ＝ tier 1–2 → 「原文條目」，其餘「相關條目」）。
     - 查詢入口表（譯法 → senseKey）**由前端從 `senses[*].renderings` 建**，用前端既有的 `foldOne` 折疊；index.json 不放這張表，折疊規則只有前端一份。
     - `lexicon`、`entries`、`entryAliases`（沿用現有知識條目連結邏輯）、`shards`（分片數）、`version: 2`。
   - `static/verseOriginal/s-<n>.json`：`{ senseKey: [[slug, verse, rendering], …] }`，依 senseKey 雜湊分片，每片目標 ≤ 150 KB（全本時自動增加分片數）。前端只抓需要的分片。
   - 舊的 `static/verseOriginalIndex.json` 停止輸出。
3. **條目連結標籤**：只有「條目的主詞就是這個原文字」（現有 tier 1、2）才標「原文條目」；只是順帶提到的（tier 3、5）標「相關條目」。修正 le.vav 被連到〈不是因你的義（tse.da.qah）〉還標成原文條目的問題。

### 前端（F，`plugins/semantic-search`）

依樣稿（使用者已同意）與 O-7～O-9：
- **入口**：讀者輸入 2–8 字；`byRendering` 找出「這個詞被和合本拿來翻」的 senseKey，處數 ≥ 2 才採用（O-9）。橋接詞、條目別名照舊可指定原文字（此時取該字處數最多的意思為預設）。單字查詢照舊不展開。超常見字（H3605、H1961、H559、H1121、H935、H6213、H5414）不展開。門檻、排除清單、上限都定義在同一個常數模組。
- **卡片**：一個 senseKey 一張，最多 3 張，依該意思的總處數排序（O-8）。卡片頭：希伯來文（`dir="rtl"`）、轉寫、意思標籤（「這裡的用法：赦免、饒恕」；只有一個意思時直接寫標籤）。
- **比例條＋譯法標籤**：依處數由多到少；含查詢詞的譯法用虛線樣式（經文已在 ① 列過）；可點，`aria-pressed`；比例條 `role="img"` 附文字說明，不只靠顏色。超過 5 種時其餘併成「其他 N」。
- **兩節對照**：「你找到的一處」（含查詢詞的一節，沒有就省略）＋「另一種譯法」（預設處數最多、不含查詢詞的譯法的第一節）；點譯法標籤換成那種譯法；「換一節」輪替同一譯法的經文。對應字用粗體＋底線標示。
- **按鈕**：「讀前後文」（連到章節頁該節）、「列出「X」N 節」（展開清單，最多 30 節＋「顯示更多」）、「這個字的其他用法：…」（列出同一原文字其他意思與處數，點了把卡片換成那個意思）。
- **說明文字**：「目前涵蓋創世記～約書亞記・依出現次數排序」；卡片內「另有 N 處，這個詞沒有可單獨對應的中文字，意思融入整句。」；區塊底部「同一個原文詞在不同經文中可能有不同用法；文字對應由資料整理，仍可能有誤，請配合上下文閱讀。」與出處（MACULA、STEP Bible）。讀者看得到的文字不出現 Strong 編號、字義編號、欄位名。
- 手機 390 寬不橫向捲動；淺色、深色模式都要好看；鍵盤可操作。
- 純函式（找卡片、排序、挑對照經文、分片計算）放 `verseSearch.ts` 或新模組並附 vitest；改 `src/` 後重建 `dist/`。
