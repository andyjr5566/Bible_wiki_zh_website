## 一、先回答：這個網站真正要教會讀者什麼？

我希望使用者離開網站時，能理解以下五件事。

1. 應許的實現，不代表立約關係就此結束。 神將地賜給以色列人，但他們仍需要在這片土地上忠於祂。
2. 立約的呼召，建立在神已經施行的作為之上。 約書亞先回顧歷史，然後才要求百姓回應。
3. 問題不是單純「要不要相信神」，而是「究竟要事奉誰」。 經文特別指出外邦神明與專一忠誠的問題。
4. 承諾具有責任和後果。 約書亞沒有因為百姓願意事奉神，就立即結束對話，反而嚴肅警告他們。
5. 這一代人的承諾，必須面對下一代的考驗。 第 24 章的結尾涉及約書亞、約瑟與以利亞撒，也為接下來的《士師記》留下重要的問題。

其中第五點，是我認為原本方案最需要補強的部分。

因為約書亞記 24 章並不是在第 28 節結束，而是到第 33 節。這個差別，會直接改變整個網站結尾的意義。

## 二、我會把原本四個階段升級為七個章節

整體互動敘事架構

1. 序幕｜已經得到的土地

   進入應許之地，為什麼還要作出選擇？
2. 第一幕｜是誰帶領你們來到這裡？

   回顧亞伯拉罕至進入迦南的歷史
3. 第二幕｜究竟是誰成就這一切？

   比較神的作為與以色列人的角色
4. 第三幕｜今日，你們要事奉誰？

   理解選擇、偶像與專一忠誠
5. 第四幕｜你們真的明白自己的承諾嗎？

   約書亞的警告與百姓的再次回答
6. 第五幕｜讓石頭成為見證

   立約、記錄、見證與責任
7. 終幕｜當這一代人離開之後

   約書亞之死、約瑟的骸骨與下一代

這七個階段不是平均切成七份簡報，而是各自使用不同的互動方式。

最重要的設計原則是：

使用者每操作一次，都必須增加一層對經文的理解。

如果一項動畫、操作或 3D 場景無法做到這點，就應該刪除，或改造成真正有教學意義的互動。

我特別想增加三種互動機制。

A. 事件記憶卡

點擊亞伯拉罕，不只是顯示「神呼召亞伯拉罕」，還可以展開創世記 12 章的相應經文，讓讀者知道這不是約書亞臨時編造的故事，而是在回顧前面的敘事。

B. 「被提及」與「沒有被提及」的對照

例如約書亞回顧了出埃及，但沒有在這段話裡詳細重述每個災難。讀者可以開啟「延伸歷史」，看到較完整的原始記載。

這能教會讀者一個很重要的閱讀方法：

約書亞不是在寫一份完整的以色列歷史，而是選取與這次立約呼召有關的歷史。

C. 神作為主詞的觀察

24:2–13 有個非常值得拿來製作互動的特點：神的話語以第一人稱反覆敘述祂如何帶領、賜予、拯救。

這不是要得出「以色列人沒有做過任何努力」的結論。整卷書明明記載了人的行動、爭戰與分地。

相反地，這個互動要讓讀者理解：在約書亞的歷史回顧裡，土地的最終來源是神的賜予，而不是以色列人可以獨自誇耀的成就。

然後進入下一個提問：

「如果這片土地是神照著應許賜給他們的，那麼，他們如今應當如何回應？」

這樣，第三幕的立約要求就不是突然冒出來的道德命令，而是整個歷史回顧自然導向的問題。

### 第三幕：今日，你們要事奉誰？

約書亞記 24:14–18

這一幕我會非常小心設計。

原本提出的「選擇事奉誰」有很高的互動潛力，但如果只是跳出兩個按鈕：

「事奉耶和華」／「事奉其他神」

就太簡化經文了。

因為約書亞的呼召並不是毫無前提的宗教投票。他已經先帶領百姓回顧歷史，接著要求他們除掉其他神明，專一事奉耶和華。

我會把這一段做成一個「判斷與論證」互動。

## 約書亞真正要求的是什麼？

閱讀 24:14–15，選出最符合上下文的理解。

選擇一位能帶來最大利益的神明

回顧神的作為，除去其他神明，專一事奉祂

只要口頭宣示忠誠即可

這裡還可以增加一個相當有意義的視覺細節：畫面並不直接讓使用者「選神」，而是呈現約書亞在經文中所提及的幾種神明背景，包括大河那邊、埃及，以及亞摩利人的神明。

點選後顯示對應經文及歷史背景，但不要自行替每個類別指定經文沒有明說的神祇名稱。

接下來，當使用者閱讀百姓在 24:16–18 的回答時，可以把他們提出的理由與第一幕的歷史事件連起來。

例如，百姓提到神帶領他們出埃及，就讓「出埃及」這張歷史記憶卡再次亮起。

這樣，讀者會真正發現：

百姓的回答不是一個孤立的誓言，而是在回應他們共同的歷史。

這不僅更忠於經文，也比單純讓石頭發光更有教育價值。

### 3. 一個跨越整卷書的「回聲系統」

我非常推薦增加這個功能。

約書亞記 24 章是整卷書的總結，所以網站應該經常讓讀者發現：

「原來前面某一章發生的事情，在最後一章再次被提起或呼應。」

例如：

| 第 24 章的主題  | 連回前文                |
| ---------- | ------------------- |
| 神帶領以色列進入迦南 | 第 1–4 章             |
| 敵人敗退與神的幫助  | 第 6–12 章            |
| 土地作為神賜予的產業 | 第 13–21 章           |
| 見證與共同身分    | 第 4、22 章            |
| 神的應許沒有落空   | 第 21:43–45、23:14    |
| 警告離棄耶和華的後果 | 第 23 章              |
| 下一代能否持守忠誠  | 第 24 章結尾，延伸士師記第 2 章 |

假設使用者在第一幕看到「神把迦南地賜給以色列人」，可以點擊一個很小的「經文回聲」圖示，展開第 21 章的相關記載。

這個系統應該區分三種關係：

直接回顧：第 24 章明確提到的過去事件

主題呼應：不同章節出現相近的詞語或神學主題

延伸閱讀：有助於理解背景，但不應視為經文直接引用

這樣能避免 AI 把所有相似內容都硬說成預表或直接關聯。

對你的聖經知識庫來說，這個「回聲系統」也能成為未來其他互動網站共用的功能。

## 六、網站操作體驗：如何讓人願意完整讀完？

我會把它設計成一個連續的單頁互動作品，但在操作體驗上提供兩種不同深度。

## 兩種閱讀模式

故事導覽模式

約 8–12 分鐘

以經文主線、關鍵互動、視覺敘事為主，適合第一次接觸聖經的人。

深入研讀模式

時間依個人探索而定

開啟完整經文、跨卷連結、歷史背景、原文及註釋差異。

兩種模式使用同一套經文資料，不需要製作兩個網站。

我還建議加入以下功能：

| 功能    | 具體設計                |
| ----- | ------------------- |
| 經文側欄  | 桌機右側常駐、手機用底部抽屜展開    |
| 閱讀進度  | 顯示已探索的章節，允許直接跳轉     |
| 跳過動畫  | 所有敘事動畫都可以略過         |
| 原文對照  | 點擊重要詞彙，查看原文資訊及可靠解釋  |
| 經文回溯  | 點擊跨書卷節點，查看原始章節      |
| 知識測驗  | 以理解經文為主，不是宗教立場測驗    |
| 閱讀記錄  | 自動儲存本機進度，方便繼續       |
| 行動裝置  | 點擊優先，避免依賴滑鼠懸停或複雜拖曳  |
| 無障礙模式 | 鍵盤操作、降低動畫、替代文字與足夠對比 |

尤其是「經文側欄」，我認為幾乎是必備功能。

因為有了它，讀者能隨時比較「網站怎麼解釋」與「經文實際怎麼寫」，不會被華麗的敘事取代了閱讀原文的機會。

另外，我不會強迫使用者完成測驗才能進入下一幕。探索可以自由進行，測驗應當是輔助理解的工具。

## 七、資訊架構：如何跟你的聖經中文知識庫整合？

這個部分我會特別重視，因為網站不應成為和原本知識庫分開的孤島。

我建議將內容分成三層：

第一層：經文證據

章節與節數、經文正文、人物、地點、時間順序、明確敘述

第二層：解經與知識連結

背景、原文、其他經文、不同註釋觀點、合理推論及不確定性

第三層：互動呈現

動畫、時間軸、地圖、卡片、對話、測驗、見證石等視覺體驗

其中第三層只負責呈現，不應成為經文內容的唯一來源。

以你的知識庫為例，可以讓 Agent 先從既有的《約書亞記》章節主檔、背景筆記與各註釋來源整理資料，再生成網站需要的 JSON。

像是某個事件的結構可以長這樣：

```
{
  "id": "joshua-24-abraham",
  "chapter": "JOS",
  "verses": "24:2-4",
  "title": "神帶領亞伯拉罕",
  "summary": "約書亞回顧神對列祖的揀選與帶領",
  "references": [
    "GEN 12:1-7",
    "JOS 24:2-4"
  ],
  "interpretations": [],
  "learning_goal": "理解立約前的歷史回顧",
  "interactions": [
    "timeline",
    "scripture_comparison"
  ]
}
```

正式資料結構還應有來源連結、註釋出處、確定程度、展示方式與多語言欄位。

## 八、我會要求開發 Agent 遵守的經文規則

這比單純要求畫面精緻更重要。

| 規則           | 原因                        |
| ------------ | ------------------------- |
| 區分經文、背景與推論   | 不讓讀者誤把解釋當成聖經原文            |
| 不替神編寫額外對白    | 約書亞記 24 章已有相當明確的神諭敘述      |
| 不自行創造歷史細節    | 例如未記載的立約儀式、人物表情、誓言內容      |
| 不將所有立約視為相同事件 | 西奈之約、約書亞記第 8 章和第 24 章各有脈絡 |
| 不把互動選擇當成真實立約 | 讀者是在理解經文，不是在網站上對神作法律式宣誓   |
| 解釋有爭議時可呈現差異  | 尤其原文、歷史背景、象徵性用語           |
| 保留第 24 章完整結尾 | 不能只做到立石為證，就忽略 29–33 節     |

我還想特別補充，網站不能讓讀者以為「得到了土地，所以就沒有任何未完成的事」。必須同時保留前面提到的第 13 章與第 21 章之間的敘事張力。

而且，整個網站不應只是勸讀者立刻作出個人宗教選擇，而是先幫助不熟悉聖經的人真正明白：古代以色列人在什麼歷史背景下被要求作出這個回應。

## 九、開發順序：哪些先做，哪些以後再加？

我會分成三個版本，避免一開始把所有精力花在特效上。

| 版本         | 製作範圍                        | 驗收目標           |
| ---------- | --------------------------- | -------------- |
| V1：完整教學核心  | 七幕、基本經文側欄、歷史時間軸、對話互動、見證石、終幕 | 能清楚理解第 24 章的論證 |
| V2：知識庫深度整合 | 示劍歷史、經文回聲、跨書卷連結、原文資料、註釋來源   | 能自行追溯經文與檢查解釋   |
| V3：沉浸體驗升級  | 示劍 3D、進階場景轉換、歷史動畫、精緻音效      | 提升吸引力但不干擾學習    |

我會以 V1 作為最重要的里程碑。

開發驗收時，不只檢查動畫能否播放、按鈕能否運作，還要找不熟悉聖經的人試讀。看他們是否能回答這四個問題：

「約書亞為什麼先回顧歷史？」「得到土地與立約有什麼關係？」「為什麼百姓答應後，約書亞還要警告？」「為什麼最後特別記載領袖的死亡？」

如果讀者能夠根據經文回答這些問題，就代表這個網站真的完成了它的教學目的。

## 十、我對整個作品的最終定位

我想把這個網站命名為：

JOSHUA 24 · AN INTERACTIVE BIBLICAL JOURNEY

# 《應許之地，未完的選擇》

約書亞記第 24 章｜一場跨越世代的立約之旅

土地已經得著，故事為何仍未結束？

回到示劍，沿著列祖的歷史，理解約書亞最後的呼召。

這個題目真正強大的地方，其實不在於立約本身有多麼戲劇化。

而是整卷《約書亞記》的敘事最後出現一個重要轉變：

前面用了大量篇幅記載以色列人如何進入、取得、分配神所應許的土地；最後卻將焦點放在這群人得到產業後，究竟會怎樣生活。

而他們之所以被要求忠誠，不是因為約書亞突然想訂立一套新的規則，而是因為在他的回顧中，這一切都建立在神過去的揀選、拯救、帶領與賜予之上。

因此，我最推薦保留的三個核心互動，是「神的作為與人的回應對照」、「百姓承諾與約書亞警告的對話」，以及「從約書亞記結尾通往士師記的世代交替」。

這三個互動，比單純做一個華麗的示劍 3D 場景更能把本章的意義傳遞給讀者。

而在所有設計中，我最希望留下的，仍是那個最後的問題：

「他們已經進入了應許之地，但當記得這一切的人都離開後，這份忠誠還能延續嗎？」

我認為，這才是能夠讓人看完網站之後，仍然想繼續閱讀《士師記》的結尾。
