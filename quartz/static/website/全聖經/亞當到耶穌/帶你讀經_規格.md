# Goal：「從亞當到耶穌」網站加「帶你讀經」（代上 1–9 章）

網站：`appendix/website/全聖經/亞當到耶穌/`。資料來源：`appendix/genealogy/build_genealogy.py`、`appendix/genealogy/歷代志上/`，用 `--export-json` 匯出。經文：`raw_scripture/歷代志上/第N章.txt`，一行一節。

要做出來的樣子：讀者按「帶你讀經」後，代上 1–9 章共 407 節逐節往下讀，可以開朗讀。讀到誰，大家譜的鏡頭就移到那個人，名字亮起來；讀到「生」，父子之間的線就用墨跡畫出來；讀到職稱，就蓋上一枚朱印。經文和家譜樹一起對著看。整體是水墨與朱印的風格，要精緻到讓人讚嘆。

## 已定案（不要再問）
- 舞台是現有的大家譜。不另畫舞台，鏡頭在這張圖上移動。
- 原本沒接上主線的 561 人，以及「新約家族」頁的 15 家，全部併進大圖。「接不上主線的家族」和「新約家族」兩頁都拿掉。
- 併進大圖的接法，依序選第一個有經文根據的：
  1. 經文寫明父母：實線，照原樣。例如耶穌的弟兄接在馬利亞底下（可 6:3）。
  2. 經文寫明是某人的後代、但沒寫隔幾代：虛線，直接接到那個人。例如以利沙伯接亞倫（路 1:5）、保羅接便雅憫（腓 3:5）、女先知亞拿接亞設（路 2:36）。
  3. 只列在某段名單裡：每段名單一塊名單牌子，例如『猶大的其他家族　代上 4:1–23』。牌子用點線掛在該段經文所屬的支派祖先或人物底下，名單裡的小家族掛在牌子下。牌子預設收起來，讀到那一段才展開。
  4. 新約裡經文完全沒寫家譜的家庭（西庇太一家、彼得一家、拉撒路一家、希律家族、亞那與該亞法、初代教會的家庭等）：放在大圖上耶穌那一代旁邊一塊『新約時代的家庭』區，各家一塊牌子，底下是自己的小家譜，不畫連到主線的線。
- 牌子掛在誰底下，要有該段經文的根據。查不到根據的人不硬接，列進回報。
- 美術是水墨與朱印。亮色模式：宣紙底、墨字。暗色模式：墨底、金字。朗讀用瀏覽器內建語音，預設關閉；關閉時文字像字幕一樣照速度亮。

## 工作
**A. 併入大圖**
- 在來源（YAML 和 build_genealogy.py 的匯出）實作上面四種接法，不要手改 genealogy.json。
- 牌子是新的節點種類，標題用讀者看得懂的段落名加經節範圍；新約的牌子用家庭名加經節，例如『西庇太一家　太 4:21』。
- 425 人原本已有段落標題（anchor 欄位，共 21 段）。另外 136 人沒有標題，多半出自尼希米記、列王紀，也照同樣規則處理。新約家族的分組和簡介沿用現有 ntFamilies。
- 拿掉 `src/ui/unconnected.ts`、`src/ui/ntfamilies.ts`（含它的測試），以及工具列分頁、`main.ts` 的頁面切換、`showFamilyPagePerson`、搜尋分流、`openPersonFamily`、人物卡的「看他所在的家族」按鈕和測試裡相關的部分。舊的 `#p=`、`#family=` 連結指向這些人時，要能在大圖上找到。
- 人物卡打開時鏡頭會避開卡片（`canvas.ts` 的 visibleArea，2026-10-15 已修好並驗證）；讀經模式的經文欄也要納入這個計算，讀到的人不能被經文欄或人物卡蓋住。
- 主線的預設畫面（fitSpine）維持不變。人數變多後，要確認畫布的效能。
- 如果歷代志上的附錄頁跟著改變，要確認是預期的改變。

**B. 逐節對照資料**
- 407 節全文收進網站資料，例如 `src/data/reading.json`。
- 每一節是一串有順序的標記：
  - 人名：對到人物。
  - 職稱：寫明屬於誰，例如祭司、族長、歌唱的、守門的、某地之祖。
  - 親屬詞：生、兒子、女兒、妻、妾，標明是誰到誰。
  - 其他：地名、族名、數字。
- 先用程式依人物資料的 `names[].ref` 和各種關係的 ref 產生草稿，再由 Opus 逐節裁決。要特別看：
  - 同一節出現兩次同名。
  - ref 是經節範圍（例如 `代上8:6-7`）。
  - 同名不同人。
  - 人名和地名同字（例如希伯崙）。
- 經文沒交代是哪一位的名字，不連到任何人，只在經文裡亮起來。
- 閘門（Python 建置和 vitest 都要擋）：
  - 每個標記的文字，在該節的指定位置逐字存在。
  - 人名對到的人物存在，而且在大圖上有節點。
  - 該節所有人物的 names 都已標記，或明確標「略過」並寫理由。
  - 407 節齊全。

**C. 讀經模式**
- 入口與版面：
  - 工具列放一個「帶你讀經」按鈕。這是一種模式，不另開一頁；進入後畫布旁多一欄經文，其他面板收起；離開時還原原本的家譜樹。
  - 章選單沿用附錄的章名，例如『第 2 章　猶大（一）：希斯崙的三個兒子』。
  - 網址 `#read=代上2:4` 可以直接打開到那一節。
  - 手機寬 390px 時，上半是畫布，下半是經文，不能出現水平捲動。
- 播放控制：
  - 播放／暫停、上一個／下一個名字（← →）、上一節／下一節、速度 0.75／1／1.25／1.5。
  - 點任一節或任一名字，就從那裡讀起。
  - 讀者拖動或縮放畫布時，鏡頭停止跟隨，並出現「回到朗讀處」。
  - 經文欄只捲動自己的容器，不能用 scrollIntoView，否則整頁會一起捲動。
- 鏡頭與高亮：
  - 同一家族相鄰的人用平移。跨很遠時（例如第 1 章的列國到第 2 章的猶大），先拉遠再推近，讓讀者看得出從哪裡移到哪裡。
  - 這一節讀過的人保持淡淡的亮，換節後慢慢退掉。
  - 沒有人名的節（例如 4:28–33、6:54–81 的城名），鏡頭停在該段所屬的人或牌子上，地名照樣亮。
- 附錄已有的「讀經提醒」，讀到那一節時在旁邊出現一小張，不打斷播放。
- 動態：
  - 預設一律有動態，不跟作業系統的減少動態設定。
  - 網站現有的「動畫」開關關閉時，鏡頭改成直接切換、不畫墨跡，播放照常進行。
- 現有導覽維持原樣，最後一站可以加一句邀請讀者進入讀經模式。
- 新的 class 一律加前綴（例如 `ag-rd-`），避免撞到舊的樣式。

**D. 水墨與朱印**
- 元素：
  - 宣紙要有細紋理。
  - 親屬線要像墨跡，有筆刷的不規則邊。
  - 名字亮起時，用筆刷遮罩由上而下顯出，外圍帶一圈墨暈。不承諾逐筆筆順。
  - 職稱的朱紅小印，讀到時「蓋」上去，經文裡和畫布節點旁各一枚。
  - 每章開頭一張章名卡（章號、章名、一枚朱印）。
- 範圍：整站只輕輕帶入紙色和墨線；筆刷顯字、蓋印、墨跡畫線這些重效果只在讀經模式出現。整體要和現有的墨色、琥珀、青綠協調。
- 字型：楷書感的開源字型（例如霞鶩文楷 TC，OFL 授權），只用在讀經模式。依實際用到的字做子集，放在網站資料夾裡，建置時不連網。授權寫在頁尾或「關於」。
- 可讀性優先：亮、暗兩種模式下，字級、行距、對比都要舒服；同時亮起的東西不能多到讀者跟不上。
- 先做樣張（亮、暗、手機各一張），用 SendUserFile 傳給使用者看，但不停下來等回覆。之後每個階段都自己截圖、自己評：筆觸、留白、對齊、節奏，哪裡不精緻就繼續修。

**E. 朗讀**
- 用 Web Speech API，優先選 zh-TW 語音，沒有就用其他中文語音。一節一句。
- 有 boundary 事件時，名字照聲音亮；沒有時，照字數估計時間。暫停、跳讀、變速時，語音要同步停下或重新開始。
- 建一份多音字人名的朗讀替換表：只改送給語音的文字，畫面上的經文不變。拿不準讀音的字列給使用者。
- 裝置沒有中文語音時，顯示一句讀者看得懂的話，例如「這台裝置沒有中文語音，可以用文字跟著讀」。
- headless Chrome 沒有語音，同步邏輯用模擬語音的單元測試驗證；真實的聲音請使用者試聽。
