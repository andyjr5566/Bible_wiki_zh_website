## 不做或延後

- 遊戲化（U-2）。
- 內容來源層次、章節狀態（U-10）。
- AI 問答與「以問題為中心的探索」：需要帶來源引用的檢索設計，之後再議。
- 自動把全庫下載到手機離線使用：之後只考慮「讀者主動選擇儲存某一卷」。
- 全面拿掉羊皮紙風格：它是網站的辨識度，只壓縮圖片、讓裝飾退到文字後面。
- 圖譜的語意連線（父子、引用、發生於…）：需要內容端提供關係類型，延後。
- 「導讀」模式的分段導讀文字：需要新內容，延後。第 7 批只做不需要新內容的部分。

## 共通規則（每一批都適用）

1. **分支**：每批一個分支，從 main 建立，可以在本地 commit。不得 push、不得合併或改動 main，除非使用者明確同意。
2. **不可改的地方**：
   - `content/`：會被同步蓋掉；首頁改在筆記庫，依 U-5。
   - `C:\Obsidian\Hermes`：只有 U-5 的 index.md 例外。
   - `.quartz/`：CI 會重新 clone 外掛，改了也會被蓋掉。
   - 能持久的修改位置：`quartz/`（含 `quartz/styles/custom.scss`、`quartz/components/`）、`plugins/<本地外掛>`、`quartz.config.yaml`、`.github/workflows/deploy.yml`。
   - 新增本地外掛時，要同時在 `quartz.config.yaml` 加項目，並在 `deploy.yml` 加 rm 與 cp 兩行（照 read-aloud 的做法）。
3. **委派**：主導者負責拆任務、寫任務包、審查 diff、整合、親自測試、和使用者溝通，**不要自己單幹**。分級照 [dev-notes/personal-notes/07-agents.md](../personal-notes/07-agents.md)：
   - Claude 子代理：`haiku` 做搜尋、機械性修改、檢查；`sonnet` 做跨檔實作，用 `isolation: "worktree"`，第一步先 `git merge --ff-only <本批分支>`。
   - Codex：`gpt-6-luna` **一律 xhigh**；`gpt-6-sol` high 只用在出錯會掉資料或有安全疑慮的工作，以及嚴格審查。
   - Antigravity：`gemini-3.8-flash-high`（**一律 high**）審中文文案與交叉審查；`gemini-4-argon-high` 附截圖做體驗審查（遇到 429 改用 flash-high）。
   - 幫手不得 commit／push、不得讀 `.env`。幫手輸出整檔時常刪掉原有註解，整合時看 `git diff -w` 的刪除行。
4. **驗證**：
   - 改動前後各拍一次無頭 Chrome 截圖：桌機 1440、手機 390、深色模式。方法見 findings.md §5。
   - `npx quartz build -d test_content -o <scratch 目錄>` 必須成功。
   - 和效能有關的批次，要用完整內容建置量測傳輸量。
   - 確認沒有回歸：wiki-tour、搜尋、SPA 換頁、個人筆記、朗讀、深色模式、PWA。
5. **紀錄**：每完成一個任務，就在 progress.md 記一行（誰、做什麼、結果、是否採用、主導者修了什麼）；新決策補進本檔的「使用者決策」。
6. **問問題**：需要使用者決定時，停下來用選擇題問，附上建議與理由，不要猜。
