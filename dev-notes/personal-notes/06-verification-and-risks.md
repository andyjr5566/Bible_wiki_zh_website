跨裝置情境（Phase 1 試用期間）：
1. Windows 寫一則 → iPhone 打開同一章，先同步後看得到。
2. iPhone 飛航模式下修改 → 出現 D-04 提示 → 確認後編輯 → 關閉飛航 → 自動合併 → Windows 看得到。
3. 兩台都離線修改同一則 → 恢復連線 → 出現「兩個版本」→ 選擇後兩台一致。
4. 一台刪除、一台修改同一則 → 出現衝突提示。
5. Windows 開兩個分頁同時編輯 → 不重複上傳、內容一致。
6. 登出並選「清除本機」→ 重新登入 → 筆記從雲端回來。

### 2.1 Phase 1 試用操作指南（P1-18，2026-10-18 部署後開始）

**目標**：用 2–3 台裝置照平常方式讀經、寫筆記兩週，**期間不可有任何筆記遺失**。發現怪怪的地方隨時回報。

**開始前（只做一次）**
1. Google Cloud 主控台 → Google Auth Platform → 目標對象：應用程式維持「測試中」，**只有列在「測試使用者」裡的 Gmail 能登入**。要找別人一起試用，先把對方的 Gmail 加進去（最多 100 位）。沒加的人按登入會看到「存取遭拒／應用程式未經驗證」。
2. 網址：`https://andyjr5566.github.io/Bible_wiki_zh_website/`。任選一個已上線的章節頁（例如〈創世記 第1章〉），捲到最下面的「我的筆記」，或點左下角「📝 筆記」。

**Windows（Chrome 或 Edge）**
1. 按「用 Google 同步」→ 看完說明按「繼續」（剛打開時會顯示「Google 元件載入中…」，一兩秒後才能按）→ 選帳號、按允許。
2. 狀態列顯示「已同步 HH:MM」和你的名字就是登入成功。
3. 授權大約一小時到期；關掉分頁再開也要重新連線。狀態列會變成「尚未連線，點「繼續同步」」，按一下就好，期間寫的筆記不會遺失。

**iPhone／iPad（Safari）**
1. 用 **Safari** 開網址（不要從 LINE、Facebook 裡直接開；它們的內建瀏覽器無法登入 Google，網站會提示改用 Safari）。
2. 登入方式同上。iPhone 的 Google 視窗通常要選帳號、按允許，屬正常現象。
3. **建議加入主畫面**：Safari 分享按鈕 → 「加入主畫面」，之後固定從主畫面圖示開啟。iOS 長期不用時可能清除 Safari 的網站資料，主畫面 App 比較不會。
4. 注意：**主畫面 App 和 Safari 的儲存空間是分開的**。在主畫面 App 裡要再登入一次；若在 Safari 有「未登入時寫的筆記」，先在 Safari 登入同步，再到主畫面 App 使用。

**試用期間要測的情境**（依序或隨機都可以；做完在下表或 10 日誌記一筆）
1. 在 Windows 寫一則 → iPhone 打開同一章：會先顯示「同步中…」，然後看得到。
2. iPhone 開飛航模式 → 按「編輯」→ 應跳出「目前無法與雲端同步」提示 → 按「我知道了，繼續編輯」→ 修改 → 關閉飛航 → 稍等或按「立即同步」→ Windows 看得到修改。
3. 兩台都斷網、改同一則 → 都恢復連線 → 兩台都出現「這則筆記在兩台裝置上同時被修改了」→ 選一個版本或「兩個都保留」→ 兩台結果一致。
4. 一台刪除、另一台同時修改同一則 → 出現衝突提示，不會默默消失。
5. Windows 同時開兩個分頁編輯不同筆記 → 內容都在、沒有重複。
6. 登出選「清除這台裝置上的筆記」→ 重新登入 → 筆記從雲端回來。
7. 在章節之間點來點去（不重新整理）→ 每一章的筆記面板都正常出現。
8. 「我的筆記」頁：搜尋、依書卷篩選、按章節標題跳回該章；每週按一次「匯出備份」留存（試用期的保險）。

**回報方式**：截圖＋哪台裝置／哪個瀏覽器＋大約時間＋做了什麼＋狀態列寫什麼。
**如果發現筆記好像不見了**：先**不要**登出、不要清除瀏覽器資料；在仍看得到筆記的裝置上按「匯出備份」，然後回報。雲端檔案有版本紀錄（V-08），可以救回。

**試用滿一週左右**（原 P0-7、V-05）：Cloud 主控台 → API 和服務 → Google Drive API → 指標／配額，截圖每日請求數與錯誤率，比對 02 的估算。

**緊急開關**：若發生嚴重問題，把 `quartz.config.yaml` 裡 personal-notes 的 `syncEnabled` 改成 `false` 並部署，所有人立刻改為只存本機（已寫的筆記仍在裝置與雲端，不會刪除）；`enabled: false` 則整個隱藏筆記功能。

**已知限制**：授權約一小時到期需按「繼續同步」（Phase 2 token 服務才能免點）；Android 與 Mac 沒有實機測過；測試模式最多 100 位使用者；網站本身的 Google 字型、Plausible 統計與筆記功能無關。

**試用通過條件**：兩週內零筆記遺失；上面 8 個情境至少各做過一次；沒有未處理的高嚴重度問題。之後決定 D-30（網域）、D-33（發佈為正式版），進入 Phase 2。

## 3. 自動化測試要求

- 單元：model（ULID、HLC、ref 解析、驗證）、merge（所有規則＋性質測試）、store、adapter（以 mock fetch）。
- 整合：InMemoryAdapter＋3 台模擬裝置，涵蓋 05 P1-14 列出的情境。
- 建置：`npx quartz build -d test_content -o <scratch>` 成功。
- 任何可能導致筆記遺失或覆蓋的改動，必須先有會失敗的測試再修。

## 4. 風險與對策

| 風險 | 影響 | 對策 |
|---|---|---|
| LINE／FB 內建瀏覽器被 Google 拒絕登入 | 大量使用者無法同步 | 偵測並引導外部瀏覽器；未登入仍可本機使用 |
| Drive v3 無條件式寫入 | 多裝置互相覆蓋 | 單一寫入者分片（D-12） |
| 同裝置多分頁同時寫 | 同一分片互相覆蓋 | Web Locks 領導分頁 |
| 使用者在 Drive 刪除 App 資料 | 雲端筆記消失 | 雲端被清空偵測＋本機重新上傳；提醒定期匯出 |
| 使用者 Google 雲端硬碟已滿 | 寫入失敗 | 明確提示，資料保留本機 |
| Safari 清除本機資料／整網域清除 | 未上傳的修改遺失 | 盡快上傳、storage.persist()、SW 快取上限 |
| 裝置時鐘不準 | 新版被舊版取代 | HLC |
| 舊版程式覆蓋新格式 | 資料損壞 | schema 檢查、未知欄位保留 |
| 配額全專案共用，有 bug 的版本讓所有人 403 | 全面停擺 | 客戶端限流、熔斷、遠端開關、分批釋出 |
| content 改版（資料夾、格式、節點名稱） | 錨點失效 | USFM 座標、防禦式偵測、失聯筆記清單（D-14、D-15） |
| 學校／公司帳號被管理員封鎖、受監護帳號 | 無法登入 | 處理 `admin_policy_enforced`，退回本機模式 |
| OAuth 停在測試中 | 最多 100 位使用者 | 公開前發佈正式版（D-33） |
| 匯入他人檔案造成 XSS | token 外洩、資料被竄改 | DOMPurify、匯入驗證 |
| 公用電腦登出後資料殘留 | 隱私外洩 | 登出時提供清除本機 |
| Google 2026 配額與計費變動 | 成本或功能受限 | 監看 Cloud Console 用量、同步層可抽換、隨時可匯出 |
| 同源（andyjr5566.github.io 下所有專案站） | 其他專案站可讀筆記與授權 | 自訂網域（D-30） |
