## 2. 分工（省 token 是硬要求）

| 誰 | 做什麼 | 不做什麼 |
|---|---|---|
| **主筆 Opus** | 所有研經內容（data/*.yaml 的文字、條目簡介、原文說明、介面上涉及經文的字句）；本批分鏡寫進 SPEC.md；契約檔改動；驗收（看總覽圖、抽查）；Codex 審查的提交與裁決；commit | 不自己寫場景／介面程式（小修例外：一兩行、驗收時發現的整合 bug）；不逐張看截圖；不重讀已讀過的檔 |
| **Sonnet `jf-engineer`** | 場景（新季節、新物件、新互動）、介面（新章、新互動 UI、月份導覽擴充）、資料腳本（新欄位、民28 數字檢查）、靜態插圖、錄影 | 不寫研經文字 |
| **Haiku `jf-collector`** | raw 索引；條目名稱確認與定義抽取；CC0 音檔候選（含授權頁證據）；跑截圖／拖曳／file:// 檢查腳本並回報數字 | 不判斷、不寫內容。它的結論主筆要抽查（第一階段它把「女性假哭」列成哀號首選） |
| **Codex（唯讀）** | 內容審查，最多 2 輪 | 不寫任何檔 |

**呼叫方式**：
- `Agent(subagent_type: "jf-engineer" | "jf-collector")`。
- 若這兩個類型沒出現在可用清單（定義檔要新 session 才載入），改用 `Agent(model: "sonnet")`／`Agent(model: "haiku")`，並把定義檔內容貼進委派訊息開頭。

**省 token 守則**：
1. 委派訊息只寫：本次任務、檔案範圍、要讀的 SPEC 段落、驗收條件、dev server 埠。不貼整份規格。
2. 要修改時用 `SendMessage` 續用同一個代理（它保有上下文），不要重開新的。
3. 讀 raw 用 `Read` 的 offset／limit，只讀索引指到的行段。
4. 截圖用 ffmpeg `xstack` 拼成總覽圖再看；有疑問的拍才開大圖。
5. 同一份檔讀過就不再讀；改完不回讀驗證（Edit 失敗會報錯）。
6. Codex 自己讀 raw；主筆不替它整理證據，只給範圍與規則（沿用 `tools/codex-review-1.md` 的格式）。

## 4. 流程（依序，能平行就平行）

1. **Haiku 索引**：
   - 本批每章 4 份註釋 raw ＋ STEP，做成 `tools/raw-index/<書卷>_<章>.md`，格式是「經節 → 每份 raw 的行號範圍」。
   - 同時用 MCP `search_wiki_entries(queries=[...])` 整批確認條目名稱，抽出各條目 `## 定義` 存到 `tools/raw-index/entries.md`。
   - 主筆抽查 2 處行號。
2. **主筆寫內容**：
   - 依索引讀相關段落；
   - 寫 `feasts.yaml`／`story.yaml`／`commentary.yaml`／`step.yaml`、`entry_gists`；
   - 把本批分鏡寫進 `SPEC.md` 新的一節，包括每拍的 cue、構圖、桌機與手機說明框位置、互動規格；
   - 需要時擴充契約檔；
   - 跑 `npm run data:check` 直到全綠。
   - GT 引文或轉述只用**同一段結尾有標記**的段落（記憶 `gt-unmarked-paragraph-attribution`）。
   - 英文引文用「原句」（中譯）。
3. **平行開工**：
   - **Codex 第 1 輪**：寫 `tools/codex-review-3.md`，範圍是本批新內容；審完 `git status util/`。
   - **Sonnet ×2**：場景一個、介面＋資料腳本一個，檔案範圍不重疊，各自用不同 dev 埠。
   - **Haiku**：新音效候選，例如大麥田的風、禾捆沙沙聲、揉麵或包麵。
     - 每個至少 3 個候選，附授權頁 URL 與授權欄位原文；
     - 主筆用 `tools/fs.mjs info <id>` 複核授權後挑選並剪輯。
4. **主筆驗收**：
   - Haiku 跑 `tools/shoot-site.mjs`（桌機／手機 × 亮／暗）、`check-drag.mjs`、`check-file-url.mjs`，主筆看總覽圖；
   - 本批新互動要在**整合後的網站、減少動態開與關**兩種情況實測；
   - 問題用 `SendMessage` 退回同一個代理。
5. **Codex 第 2 輪**（若第 1 輪有 finding）：
   - 只看修改處；
   - 第 2 輪之後由主筆做最後修正，不叫第 3 輪；
   - 紀錄寫進 `tools/review-log.md`。
6. **收尾**：
   - `npm run build` 全過；
   - 補 `public/fallback/` 新 cue 的插圖；
   - 錄 4 支影片放 `review/`；
   - 更新 `HANDOFF.md`；
   - commit 一次；
   - 回報。
