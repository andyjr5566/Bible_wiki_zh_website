## 產品必須回答的問題

讓一般讀者透過可操作的 3D 場景，清楚知道會幕怎麼分區、六件核心器物在哪裡與怎麼使用、不同角色在哪裡供職、獻祭有哪些不同程序，以及贖罪日與日常服事的差別。每一項說明都能點開證據，讀者能辨認經文明載、考古比較、視覺示意和未能確定的細節。

「成熟」的完成條件是這條學習路徑完整可用。漂亮首頁、發光特效、影片運鏡或新增模型數量都不能替代它。場景須以聖經描述為約束；資料沒有提供的外貌／曲線／動作，不以寫實造型冒充已知歷史。教學鏡頭可以觀看幔內，不能把相機自由度說成古人通行權。

核心程序：祭司洗濯、燈臺服事、陳設餅、日常獻香、燔祭、贖罪日。利未記五祭比較涵蓋燔祭、素祭、平安祭、贖罪祭、贖愆祭；各分支有資料驅動的步驟與區域高亮，不要求把沒有資料的動作做成寫實表演。人物工作涵蓋獻祭者、普通祭司、大祭司、利未人／指定協助者的職責區分，以及有來源支撐的祭司服飾。不可用「通用人物仍未準備好」永久省略誰做什麼的教學。

## 已決定的設計

1. 保留 Vite、strict TypeScript、Three.js、Zod 與現有分層，依需求修正；不重建第二個 loader 或回復舊 JavaScript 場景。
2. 以剋制的博物館導覽風格呈現：深色導覽列、淺色閱讀面板、銅／金作少量重點色。3D 主角有充足畫面；移除裝飾性表情圖示與「電影級」自我宣傳。
3. 桌面預設完整會幕；點選器物直接進可靠的獨立特寫，底層載入策略由 runtime 管理。框架是構造探索，低模是明示的備援；不因手機 UA 偷換成低模。允許修改既有 profile 契約完成此目標，須同步 schema、tests、檔案。
4. 選取／導覽／程序／相機只使用同一個選取脈絡；任何時刻至多一個自動播放控制者。手動拖曳暫停自動鏡頭，退出還原原本位置、剖面、品質與選取。
5. 預設閱讀光照穩定，聲音由使用者開啟，支援 reduced motion。移除把固定光柱、圓球光暈、永燃三角火焰當成歷史外觀的效果；有經文事件依據的雲火只能在對應事件、附證據與示意標示後呈現。
6. 面板先回答「這是什麼／誰使用／在何處／依據哪段」，原文、詳細比較、署名放可展開區。完整經文與摘要明確區分。無來源的原文拼寫先移出可見介面；不可由模型補字。
7. 學習程序採非寫實動作提示。涉及血、宰殺等有經文記載的步驟，清楚以文字與抽象標記說明，不能因避免血腥而省略程序，也不增加戲劇對白、禱詞、音效或表演。
8. 不以「一年一次」推成「贖罪日只穿越幔子一次」；也不把至聖所描述成一般人日常獻燔祭的地方。精確內容依來源任務複核。

## 實作分工與停點

Luna 每次只領一張任務卡，讀完輸入、記錄開始狀態、修改允許範圍、執行驗收，然後寫進度與下一任務 ID。使用者手動切換模型後直接繼續，不必另外啟動子代理。若採子代理，使用者已授權 `gpt-5.6-luna`，但要先確認實際呼叫成功；模型清單有名稱不等於已成功執行，不可靜默改用其他模型。

Blender 始終只有一個場景寫入者。R00 先檢查當前場景是否已存檔，保留使用者原工作；R07 之後只在隔離場景或獨立 background process 執行。禁止把清空使用者場景當初始化。可用平行工程代理時，只分派不互相寫同一檔案且不依賴未完成契約的工作；本清單預設循序，不以平行省略依賴。

來源不明、經文互相處理方式不明、跨層契約衝突：記入 unresolved，列出具體來源／檔案、兩種解法及影響任務，交 GPT-6 裁定。日常可逆工程選擇自行完成。Luna 不需要反覆詢問是否可以執行已列明的任務，但不得自行免除驗收或把歷史猜測改標「經文明載」。

## 完成規則

R00–R23 是 Luna 實作與自驗；透過後標「待總控驗收」。GPT-6 的 R24 才能標整站完成。允許來源不確定部分以明確未詳載或有根據的比較呈現，但核心學習功能不得留下 TODO、只有一個 placeholder 步驟或全數角色缺席。

維持原始來源 GLB、source hash、下載／授權紀錄、使用者研究檔；修改只產生衍生檔。庫根經文、註釋、研經 production 與 `.tmp` 不由本工程改寫。本站自有 JSON 的精確經文抽取、對照註解及來源標記可依本規格維護，不啟動章節 M3/M6 production 流程。

最後交付可本機 production preview、可部署的 dist、完整原始碼／Blender 重建材料與 QA 證據。正式發布、外部同步與公開 PR／訊息不包含在本批自動動作。發布需使用者另有指示。
