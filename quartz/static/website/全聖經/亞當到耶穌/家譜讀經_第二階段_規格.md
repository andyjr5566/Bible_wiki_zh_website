# 規格：「從亞當到耶穌」帶你讀經第二階段：一趟讀完其餘家譜、大衛立的職位、歸回的人

網站：`appendix/website/全聖經/亞當到耶穌/`。第一階段（代上 1–9，407 節）已完成；它的做法、閘門、水墨與朱印美術全部沿用（見 `帶你讀經_規格.md`）。本檔是第二階段唯一的權威規格，2026-10-16 與使用者逐項討論定案。

## 一、這次要做出來的樣子

讀者按一次「帶你讀經」，從創世記一路讀到路加福音。聖經裡許多名字擠在一起，網站一邊唸，一邊用畫面帶過：讀到誰，誰就亮起來、秀出來。

- **同一趟讀經，畫面自己換。** 經文欄固定不動（桌機在右、手機在下）。上方的畫面跟著「這幾節在講什麼」來換，而不是跟著章換：
  - 講「誰生誰、誰的妻子兒女、誰的子孫」→ **家譜樹**（現有大圖）。
  - 講「誰擔任什麼職位、哪一班」→ **職位圖**（新分頁「大衛立的職位」）。
- **換畫面時**：出一張標題卡（例如「大衛的勇士　歷代志上 第 11 章」），原來的畫面縮成角落的小地圖，新畫面浮上來。讀者可以點小地圖偷看另一個畫面；看的時候讀經暫停跟隨，按「回到朗讀處」回來。手機上小地圖縮成一個按鈕。
- **家譜樹的主線不加任何新人。** 職位圖上的人，家譜樹上已經有的（約押、亞比篩、撒督、亞薩……），在樹上的卡片旁蓋職位印（「元帥」「勇士」「第三班」）；印讀過就留著，平常不讀經時也看得到，點印跳到職位圖。
- **樹上沒有的人**只住在職位圖裡：名字亮、小卡寫他是哪裡人、擔任什麼、出處經節，不硬掛到家譜樹。
- **經文寫明父親、而父親已經在樹上的人**，照第一階段的規則「經文寫明父母就接實線」加進家譜樹的旁支（例如代上 27:5「祭司耶何耶大的兒子比拿雅」→ 掛在祭司耶何耶大底下，前提是確認兩處的耶何耶大是同一人）。
- **一人多職**：讀到他時，職位圖上他的每個職位一起亮，旁邊小卡列出全部職位與經節，可以「在家譜樹上看」。
- **歸回的人連回祖先**：讀以斯拉記、尼希米記的名單時不開新畫面；讀到哪一家，就把那一家的祖先在家譜樹或職位圖上亮起來。祖先在前面的經文出現過、而且有根據的才連；沒有的就只讀過、名字亮起，不硬連。最重要的一幕：職位圖的「祭司二十四班」環上，回來的那幾班變紅（耶大雅、哈琳、音麥），第七班哈歌斯畫虛線並寫出拉 2:62「在族譜之中尋查自己的譜系，卻尋不著」。
- **平行經文差異小卡**：同一份名單在兩處寫法不同時，讀到那一節旁邊出現一小張，只寫兩處各自的寫法和經節，不解釋原因。

## 二、以聖經為主：資料的根據與順序

所有內容先回到經文；其他資料只用來確認，不用來增加經文沒說的事。依序：

1. **經文本身**（`raw_scripture/`，和合本）：經文文字、人物關係、職位、誰是誰的兒子，只取自這裡。前後文能判斷的，以前後文為準。
2. **原文證據**（STEP Bible：`raw_data/stepbible_*.txt`、`.stepbible_data/`，MCP `query_step_context`、`find_step_occurrences`）：同名的人，原文的擴充 Strong 編號常會用不同字母區分不同的人，用來確認或推翻「是不是同一人」。STEP 沒有列出不等於否定。
3. **四套註釋**（`raw_data/` 的 CT、GT、KC、BH）：例如 GT 說耶大雅、音麥屬大衛時代的祭司班次（代上 24:7–14），BH 說哈哥斯是第七班（代上 24:10）。註釋只能支持經文已經指向的連結，不能自己創造連結。
4. **權威外部資料**（輕度參考）：STEPBible-Data 的 TIPNR（人名地名對照表，CC BY 4.0），可下載放進 `appendix/genealogy/sources/` 並註明出處，用來交叉檢查同名的人。其他外部資料只能用出版的聖經辭典、地圖集這類權威著作，寫明出處；不引維基百科。外部資料和經文或註釋衝突時，以經文為準，並把衝突列給使用者。

每一個「連結」都要寫明根據，存在資料檔裡（`basis:` 欄位），建置時檢查：
- 經文根據：經節，且經文裡確實有那幾個字。
- 註釋根據：`raw_data` 檔名與逐字引句，程式逐字比對該檔確實有這句。
- 外部根據：資料名稱、版本、條目。

讀者看得到的小卡只寫經文和經節；必須引用註釋時，照 AGENTS.md：英文原句放「」、中譯放（），或具名轉述。

## 四、職位圖（分頁「大衛立的職位」）

一張組織圖，大衛在上，分四類；每類底下是職位方塊，方塊裡是擔任的人（人名小卡；樹上有的帶「樹」字樣，點了到家譜樹）。

| 類別 | 經文 | 畫法 |
| --- | --- | --- |
| 王的身邊 | 代上 18:14–17、27:32–34；撒下 8:15–18、20:23–26 | 元帥、史官、書記、祭司長、統轄基利提人和比利提人、謀士、王眾子的師傅、王的陪伴、宰相、掌管服苦的人。三份官員名單寫法不同處出差異小卡（例如書記：代上 18:16 沙威沙、撒下 8:17 西萊雅、撒下 20:25 示法）。 |
| 軍隊 | 代上 11:10–47、12:1–40、27:1–15 | 勇士分「三個勇士」「三十個勇士」；投奔大衛的人依支派分組；十二班軍隊畫成十二個月的輪盤，每班二萬四千人（27:1）。 |
| 聖殿與利未人 | 代上 15:4–24、16:4–6、16:37–42、23:1–26:32 | 利未人三萬八千照四種職務並列，只照經文寫數字，不畫比例圖（23:3–5）；祭司二十四班畫成二十四格的環（24:7–18），第八班亞比雅（24:10）連到路 1:5 撒迦利亞；歌唱的分給亞薩、希幔、耶杜頓的子孫（25）；守門、府庫、官長和士師（26）。 |
| 支派與產業 | 代上 27:16–31 | 管理眾支派的首領、掌管王產業的人。 |

- 歸回的那一層（第 28、30、32 段讀到時）：二十四班環上子孫歸回的那幾班變紅、族譜尋不著的畫虛線；守門、歌唱的方塊也標出「子孫歸回」並連到拉 2 的經節。
- 讀經時職位圖的「鏡頭」：亮起那個方塊與人名、蓋職位印，必要時捲動到那一區（只捲職位圖自己的容器，不用 scrollIntoView）。
- 同名不同人要分開：例如代上 27:25「烏西雅的兒子約拿單」和 27:32「大衛的叔叔約拿單」；「哈律人沙瑪」（代上 11:27）不是家譜樹上的沙瑪；當勇士的「耶何耶大的兒子比拿雅」（代上 11:22）和樹上另外兩個比拿雅不同人。

## 五、歸回的人連回祖先（第 28–32 段）

逐家判斷，三種結果，都要寫 `basis:`：
1. **連回職位圖**：祭司耶大雅、哈琳、音麥的子孫（拉 2:36–39）→ 二十四班第二、三、十六班（代上 24:7–14；GT、BH、KC 支持）；哈哥斯的子孫（拉 2:61）→ 第七班哈歌斯（代上 24:10；BH 支持；中文寫法不同，小卡兩種寫法都列）；歌唱的亞薩的子孫（拉 2:41）→ 亞薩（代上 25:1）。
2. **連回家譜樹**：守門的沙龍、亞谷、達們的子孫（拉 2:42）→ 代上 9:17；巴西萊的子孫（拉 2:61，經文自己說先祖娶了基列人巴西萊的女兒）；所羅門僕人的後裔（拉 2:55–58）→ 所羅門；法勒斯的子孫（尼 11:4–6）→ 法勒斯。
3. **不連**：前面經文沒有交代祖先的家族（拉 2:3–19 巴錄、巴哈摩押、以攔、薩土……）、照城邑算的（拉 2:20–35）、尼提寧與不能指明譜系的（拉 2:59–60）：名字亮起、照讀，不連。
上面列的是已查證的例子，不是全部；其餘每一家都照同樣標準逐一查。拉 2 和尼 7 寫法或人數不同處出差異小卡。讀到拉 2:62 時，旁邊出一張小卡連回代上 9:1「以色列人都按家譜計算」。

## 六、家譜樹的新資料

- 新段落逐節對照，做法同第一階段：程式依人物資料出草稿，Opus 逐節裁決；閘門按段落：位置錯誤 0、找不到人物 0、未處理的人名 0；經文和 `raw_scripture` 逐字相同。
- 要特別看：同名不同人（創 4 和創 5 的以諾、拉麥；創 36 同名族長）；路 3「某某是某某的兒子」的反向寫法（墨線方向要對）；太 1「某某生某某」；只出現一次的女性與外邦人。
- 加進樹的新人（父親已在樹上者）照現有的 people yaml 與大圖安置規則處理；全部展開不重疊、版面計算時間、點人物不被人物卡蓋住的全員檢查都要照樣通過。
- 職位印存在資料裡（人物 id → 職位、經節），建置時匯出；家譜樹讀這份資料畫印。

## 七、讀經程式（給工程子代理的介面要求）

- 讀經資料改成「一串段落」，每段有：書卷、起訖節、標題、舞台（可在段內切換）、上一段／下一段。舊的 `#read=代上2:4` 照常可用；`#read=創5:3`、`#read=代上24:10`、`#read=拉2:61` 都能直接打開，並切到該節的舞台。
- `reader.ts` 不再直接呼叫畫布，改成呼叫「舞台」介面（移鏡頭、標亮、展開、畫墨線、蓋印、捲動）。家譜樹和職位圖各實作一份。Opus 先寫好共用型別與介面，再分給子代理。
- 換段：章名卡、先拉遠再推近（第一階段已修好跳讀時不飛的問題，換舞台時同樣要有過場）；讀完一段自動接下一段；段落選單依路線分組。
- 小地圖：顯示另一個舞台的縮影與「目前讀到的人」的位置點。
- 資料分檔：家譜樹路線與職位圖各一個 JSON，職位圖分頁打開或讀到時才載入。
- 起點：第一次按「帶你讀經」從創 4:17 開始；之後再按，從上次讀到的地方接下去。尼 7 整章照讀，和拉 2 寫法或人數不同的節出差異小卡。

## 八、朗讀

新段落的人名都跑多音字檢查：用 Windows 中文語音（Microsoft Hanhan）把原詞和同音、不會唸錯的寫法各唸一次比頻譜，分數太接近時改用整句（記憶 `tts-polyphone-check-by-waveform`）。唸錯的加進 `src/data/speech-fixes.ts`（只改送給語音的文字）；拿不準的列給使用者。檢查腳本放進 `scripts/`。

## 九、分工

**Opus（主 session）**：段落起訖、舞台切分與標題；逐節裁決（名字是誰、職稱屬於誰、同名不同人）；哪些人加進樹；職位資料；歸回的人連回祖先的判斷與根據；差異小卡文字；所有讀者看得到的文字；職位圖版面與美術方向；整合；截圖驗收；回報。

**Sonnet 子代理（effort high）**，照 Opus 寫好的型別與介面做，每個只碰自己的檔案：
- S1 讀經程式：段落資料、舞台介面、自動換畫面、標題卡、小地圖、段落選單、`#read=` 路由（`src/ui/reader.ts` 與新的 stage 模組）。
- S2 職位圖：組織圖、二十四格環、十二月輪盤、人名小卡、一人多職高亮、歸回層（新的 `src/ui/roles*.ts` 與樣式）；家譜樹上的職位印（`canvas.ts` 只加印的繪製）。
- S3 驗收腳本：讀經功能驗收擴充到兩個舞台與換段、截圖腳本、點人物不被蓋住的全員檢查（scratchpad 的 `browser_tools`）。

**Codex（gpt-6-luna）**，界線清楚的程式；workspace-write 失敗就改給 Sonnet，不要卡住；使用前照記憶 `codex-cli-must-be-current`、`codex-sandbox-node-repl-lock` 檢查；規格裡寫明「中文用檔案編輯工具寫，不要經過 PowerShell 管線」，交回後掃 `??` 與 `\u` 跳脫：
- C1 平行名單逐名對齊（代上 1 對創 5、10、11、25、36；撒下 5:14–16 對代上 3:5–8、14:4–7；拉 2 對尼 7；代上 18:14–17 對撒下 8:15–18、20:23–26），輸出差異草稿與測試。
- C2 TIPNR 下載與解析：產生「本次段落裡每個人名在 TIPNR 的對應人物」對照表（附出處與版本），給 Opus 裁決同名用。
- C3 根據檢查器：檢查資料裡每個 `basis:` 的經節存在且含那幾個字、註釋引句逐字存在於該 raw_data 檔。
- C4 多音字波形檢查腳本（把 scratchpad 的 `tts_wav.ps1`、`tts_compare.py` 整理成正式腳本，含使用說明）。

**Haiku**，機械核對，結論一律由 Opus 回查：
- H1 每段疑似人名清單、同段同名、同名在前面經文出現的位置。
