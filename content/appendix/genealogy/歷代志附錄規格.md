# 歷代志人物附錄規格

把歷代志整卷的人物附錄做完。現有的 1–9 章族譜頁不動，另外新增四頁：代上 10–29、代下猶大列王、南北國列王對照、總覽。每完成一頁就驗證並 commit 一次。

## 已定案的決定（不要再改）
- 範圍：以人物為主。事蹟只在「南北國列王對照」頁用散文寫。
- 和撒母耳記、列王紀的對照：只列事實，例如「列王紀有、歷代志沒寫」「歷代志多寫」。全部都要能用和合本逐字驗證，不解釋原因。
- 年代：採 Thiele 年表，並當作年代圖的主軸，從掃羅開始。Thiele 沒有給掃羅、大衛的年代，這兩段另外引用一個有出處的來源，並標「推估」。表頭寫明年表出處，並說明這些年代不是經文本身的資料。經文裡「猶大王某某第幾年，以色列王某某登基」這類對照紀年，照字面列出；和年表對不齊的地方加「讀經提醒」，不要自己去圓。年表數字一律加「約」。
- 年代圖：由 build 程式產生內嵌 SVG，因為 mermaid gantt 不支援公元前的年份。要支援暗色模式（沿用現有頁面的半透明底色），共治期用較淡的色段畫出重疊。用 headless Chrome 截圖，看亮色、暗色和手機寬度。
- 王的評語分三類，照經文原句：
  - ● 行正：「行耶和華眼中看為正的事」，沒有但書。
  - ○ 行惡：「行耶和華眼中看為惡的事」。
  - ◐ 有但書或前後轉變：例如亞撒有「只是邱壇還沒有廢去」（王上 15:14），亞瑪謝「只是心不專誠」（代下 25:2），耶戶在王下 10:30–31，瑪拿西在代下 33:13 悔改。
  - 分類依據是有明文評語的那一卷。兩卷都有評語但不一致，或其中一卷多寫了轉變時，王名旁加「兩卷不同」記號，對照表並列兩卷的原句和經節。例如亞比央（亞比雅）：王上 15:3 寫行惡，代下 13 章沒有評語句式。
- 頁面（檔名固定）：
  1. `appendix/歷代志上的完整人物支線圖.md`：現有的 1–9 章，不改名，只加系列導覽。
  2. `appendix/歷代志上的大衛王朝人物圖.md`：代上 10–29。
  3. `appendix/歷代志下的列王人物圖.md`：代下，只用歷代志的猶大王卡片。
  4. `appendix/南北國列王對照.md`：同時引用列王紀、歷代志和先知書。
  5. `appendix/歷代志人物總覽.md`：入口頁。
  - 完成後把新頁加進 `appendix/index.md` 的「人物支線圖」。
- 不連到 link_folder 條目。這五頁彼此之間可以互相連結（程式要開白名單），其他跨檔連結仍然禁止。
- 分支：目前的 workflow-maturity-2026-09-29。一頁一個 commit，共 5 個。訊息格式照之前的「歷代志上 1–9 章族譜附錄：…」。本規格檔隨第一個 commit 一起提交。

## 各頁內容

### 代上 10–29（組織圖：按職分分組，不按血緣）
- 第 10 章掃羅之死只寫一小段，接回族譜頁 8:33、9:39 的掃羅家。
- 第 11–12 章：大衛的勇士（三個勇士、三十個勇士），以及投奔大衛的人（洗革拉、山寨、希伯崙，各支派的人數）。人數併入「經文記下的人數」表；和撒下 23:8–39 的名字差異放進平行經文對照表。
- 第 15–16 章抬約櫃、歌唱、奏樂的利未人；18:14–17 大衛的臣僕（對照撒下 8:15–18）。
- 第 23–27 章：利未人的分班、祭司二十四班（照掣籤的次序）、歌唱二十四班、守門的、管庫的、十二個月班、各支派的首領、管理王產業的官員、謀士。
- 族譜頁已出現過的人，例如亞薩、希幔、以探、撒督，旁邊標出族譜頁的經節，並連到族譜頁的錨點。
- 每一節都要有資料涵蓋，這條規則只套用在名單段落；敘事章節在 uncovered 寫明理由。

### 代下（只用歷代志）
- 猶大的王（含所羅門和亞他利雅）每位一張卡片。欄位：父親、母親、登基年歲、在位年數、代下的評語原句和分類記號、同時代的先知、先見、祭司、葬在哪裡、列王紀的平行經節、Thiele 年代。
- 附表：
  - 歷代志引用的史書（逐字）
  - 大衛家和亞哈家通婚的小家譜圖
  - 每位王佔幾節的長條圖
  - 平行經文的事實對照
  - 同名不同人
  - 先知與祭司表
  - 代下 36:22–23 的古列結尾
- 每張卡片連到「南北國列王對照」頁的同名段落。

### 南北國列王對照
- 頁首放年代 SVG：南北兩條線，從掃羅開始；每段依評語上色（三類），「兩卷不同」的王另加記號。
- 評語對照表：王、評語原句、經節、分類、但書或轉變的原句。南北各一張。
- 每位王一小段散文（3–5 句）寫他的事蹟。可以用王上、王下、代下和先知書的內容，例如耶 36 章約雅敬燒書卷、耶利米和西底家的對話、摩 7 章耶羅波安二世、賽 36–39 章希西家。每句都要能對回所附的經節，「」內逐字。經文沒寫的事不從神學常識補，也不寫學者的推論。
- 「列王紀和歷代志寫法不同」表：只並列兩卷的原句和經節，不解釋原因。
- 北國的王：歷代志有提到的，標出代下的經節。

### 總覽
從族譜頁接下來的主線（亞當 → 大衛 → 歷代的王 → 被擄、歸回），一張縮小版的南北國評語分布圖，四頁的篇幅長條圖，以及全系列目錄。

## 程式
- 擴充 `appendix/genealogy/build_genealogy.py`，不另外寫第二支程式。新增的資料類型：
  - `roster`：按職分分組的名單，可以有子分組和人數。
  - `kings`：王的卡片、評語分類、兩卷差異。
  - `reign_prose`：每位王的事蹟段落，附經節清單。
  - 年代 SVG 渲染器。
- 「每一節都要涵蓋」的檢查改成按段落套用。
- 開放五頁之間互相連結的白名單。
- 頁首加系列導覽。
- 新增的驗證規則：
  - 評語分類的原句必須逐字出現在所引經節。
  - 事蹟散文每段至少附一個經節，「」內逐字。
  - 經節可以引用到先知書（ABBR 已經涵蓋全部書卷）。
- 資料放在 `appendix/genealogy/歷代志上/`、`appendix/genealogy/歷代志下/`、`appendix/genealogy/南北國列王/`。年表資料附上來源網址或書目。
- 現有的驗證規則一條都不能放寬，經文以 `raw_scripture/` 為準。
- 現有的 1–9 章頁面重新產生以後，除了加上導覽，內容不能有任何變動（用 diff 確認）。

## 分工（省 token）
- **Opus（主 session）**：
  - 頁面設計、白話說明、人物介紹、讀經提醒
  - 每位王的事蹟散文、評語分類的最後判定、兩卷差異的取捨
  - 逐段複核關係是否正確、截圖驗收
  - 研經相關的文字只由 Opus 寫，不准靜默改用 Sonnet 或 Haiku。
- **Codex Luna**：照規格擴充 build_genealogy.py 和 SVG 渲染器。codex-cli MCP 可能連不上，用命令列 `codex exec -m gpt-6-luna --sandbox workspace-write -C <repo> - < spec.md`。先用 `codex --version` 確認是最新版。規格寫明「中文用檔案編輯工具寫，不要經過 PowerShell 管線」。交回以後先 `grep -n "[?]\{2,\}"` 檢查中文有沒有變成問號，再看 diff，然後 `git status` 確認它只碰了規格內的檔案。
- **Sonnet 子代理**：照規格從 raw_scripture 起草 roster、kings 的 YAML 資料（人名、關係、經節、評語原句），跑 --check 到通過。交回後由 Opus 逐段核對。
- **Haiku 子代理**：機械性的蒐集，交回 TSV（書卷、章、節、原句），結論一律由 Opus 抽查複核。蒐集項目：
  - 每位王在王上、王下、代下的經節範圍
  - 評語句式和但書所在的經節
  - 對照紀年經文
  - 母親名字的經節
  - 先知書提到每位王的經節（要分辨同名的王，例如南北國都有約阿施、約蘭）
  - Thiele 年代的原始數據和出處
- 子代理需要程式脈絡時，由主 session 先用 run_pipeline 取得，再把結果交給它，不讓它自己廣泛搜尋。不要整份讀 115KB 的現有頁面，看 yaml 和需要的段落就好。

## 每頁的完工條件
1. `python appendix/genealogy/build_genealogy.py <資料集> --check` 通過，並產生頁面。
2. 用 --review 輸出逐節對照表，Opus 抽查。
3. Codex 唯讀複核一次（--sandbox read-only），只列可以驗證的錯誤，例如關係錯、經節錯、引句錯、評語分類和原句不符、散文寫了經文沒有的事。Opus 修完不再送第二次。複核後先 `git status util/ appendix/genealogy/`，確認它沒有改程式。
4. headless Chrome 截圖：亮色和暗色模式都看；手機寬度不能出現水平捲動。
5. verify_links 離線掃描，BROKEN、INVALID、UNKNOWN 都是 0。
6. commit。

## 寫作
- 繁體中文，寫給一般讀者：先講白話結論，段落要短，人名照和合本。和合本的女性主詞用「他」。
- 不要 AI 腔：不用「不是X而是Y」的對仗句，句尾不加空泛的昇華，不寫「本次」「維護」「舊版」這類流程用語。
- 事蹟散文照時間順序寫事實。評價只引用經文自己的評語，不加「他是個好王」這類判斷。

## 不確定時
遇到需要使用者決定的事（例如某位王要歸哪一類、某段名單要怎麼分組、先知書的某段經文要不要算進某位王），用 AskUserQuestion 選項題問，每題 2–4 個選項，推薦的放第一個。不要自己猜一個預設值帶過去。
