## 產品與使用者體驗

### D-01｜2026-10-18｜定案｜使用者
**採用 Google 登入 + 每位使用者自己的 Google Drive 保存筆記**，網站不集中保管任何人的筆記。
理由：資料自主、網站零保管責任、在可預見規模內 API 免費（見 02 §4）。
注意：省錢優勢沒有想像中大（同規模 Firestore 約 0–25 美元／月），真正價值是隱私與資料歸使用者。

### D-02｜2026-10-18｜定案｜使用者（經澄清）
**同一個帳號在所有裝置上永遠只看到同一份筆記。** 不會出現「每台裝置各有一份進度」。
「每台裝置一個分片檔」只是雲端內部的儲存方式（使用者看不到），讀取時一律合併成帳號層級的單一視圖。
使用者原本擔心「像遊戲同帳號不同裝置有不同進度」，這個設計不會發生。

### D-03｜2026-10-18｜定案｜使用者
**先同步再編輯。** 登入狀態下：開啟筆記面板、我的筆記頁、或開始編輯某則筆記時，若距上次同步超過 30 秒，先從雲端拉取最新內容，完成後才開放編輯（通常 1–2 秒）。上傳前也先檢查雲端更新。
詳細狀態機見 03 §5。

### D-04｜2026-10-18｜定案｜使用者
**無法同步時跳提示，使用者確認後才可離線編輯。**（選項「跳提示，確認後可編輯」）
提示文案要如實：修改不會覆蓋其他裝置的內容，最壞情況是同一則筆記產生兩個版本讓使用者選。建議文案：

> 目前無法與雲端同步（沒有網路或尚未連線 Google）。
> 你現在的修改會先存在這台裝置，恢復連線後會自動合併。
> 如果其他裝置也修改過同一則筆記，系統會保留兩個版本讓你選擇。
> 〔重試同步〕〔我知道了，繼續編輯〕

### D-05｜2026-10-18｜定案｜使用者
**未登入也可以寫筆記，只存在這台裝置。** 第一次登入時詢問「要把這台裝置上未登入時寫的 N 則筆記加入此帳號嗎？」〔加入〕〔先不要〕，避免公用電腦上混入別人的筆記。
理由：降低門檻；照顧沒有 Google 帳號的使用者（不少 iPhone 使用者）。

### D-06｜2026-10-18｜定案｜使用者
**實機測試裝置：iPhone／iPad、Windows 電腦。** 沒有 Android 與 Mac。
影響：Android 只能用 Chrome DevTools 模擬與社群資料推估，列為已知缺口（06 §2）。

### D-07｜2026-10-18｜定案｜使用者
**開發方式：一次把討論與結論完整記在本資料夾，之後分階段執行。** `/goal` 提示詞要註明可使用幫手：Claude 子代理、Codex（Luna／Sol 模型）、Antigravity。見 07、09。

## 技術架構

### D-10｜2026-10-18｜定案｜Claude（使用者同意整體方向）
**本機優先：** IndexedDB 是介面讀寫的唯一來源，Google Drive 是同步與備份層，不是資料庫。

### D-11｜2026-10-18｜定案｜Claude
**只申請 `drive.appdata` 一項權限**，同步本體放在 appDataFolder（使用者在 Drive 看不到，App 以外的程式也讀不到）。
理由：非敏感權限、不需安全評估；只有一個非登入類權限時 Google 不顯示勾選框，使用者不會只同意一半；使用者不會誤改檔案。
名稱與頭像改用 Drive `about.get?fields=user` 取得（接受 drive.appdata）。
`drive.file`（使用者看得到的 Markdown 備份）留到 Phase 3，由使用者主動開啟時才漸進申請。

### D-12｜2026-10-18｜定案｜Claude
**每台裝置 × 每卷書一個分片檔，每個檔只有一個寫入者。**
理由：Drive API v3 已移除 ETag／條件式寫入 [事實]，多裝置寫同一檔會默默互相覆蓋。分開寫入者可從根本避免。
否決：單一大 JSON、每章一檔＋manifest.json、每筆一檔（理由見 02 §6）。

### D-13｜2026-10-18｜定案｜Claude
**合併以「筆記 ID」為單位，用 HLC（混合邏輯時鐘）排序；同時修改保留兩個版本。** 刪除用墓碑標記，至少保留 365 天。
不採用 CRDT 函式庫（Automerge／Yjs）：個人筆記不需要逐字協作，成本不划算。

### D-14｜2026-10-18｜定案｜Claude（因使用者告知 content 仍在建置）
**經文座標用 USFM 書卷三碼，格式 `BOOK.章.節`（如 `GEN.10.5`），不用網址 slug 當主鍵。**
（研究報告初稿寫「OSIS」，正式採 USFM 三碼：全大寫、固定長度，適合當檔名。對照表見 03 附錄 A。）
書卷由章節頁路徑開頭的兩位數編號推得（`01-…/第10章` → GEN），不依賴書卷名稱文字。

### D-15｜2026-10-18｜定案｜Claude（因 content 仍在建置）
**MVP 先做整章筆記**，資料格式保留經節範圍欄位，使用者可手動輸入節數（如 5-7）。
點選經節的介面（需要在建置時替經節 `<li>` 加 ID）等章節格式穩定後再做（Phase 2）。
人物／地點／主題節點筆記放到 Phase 3（節點名稱在建置期間變動最大）。

### D-16｜2026-10-18｜定案｜Claude
**MVP 用 GIS Token model（純前端，不需後端）。** 代價：token 約 1 小時、沒有 refresh token、續期需使用者點擊；關閉瀏覽器再回來要點一次「連線同步」。
Phase 2 加無資料庫的 Token 服務（GIS Code model）以達成免點擊續期與 iPhone 主畫面 App 登入。
若 PoC 發現 iPhone 主畫面 App 完全無法登入，可把 Token 服務提前（待決 D-31）。

### D-17｜2026-10-18｜定案｜Claude
**新功能封裝成獨立 Quartz plugin `plugins/personal-notes/`**，沿用 `plugins/wiki-tour` 模式（tracked、dist/ 進版控、CI 複製進 `.quartz/plugins`）。
可在 quartz.config.yaml 用 `enabled: false` 整個關閉。不改 content 經文、不改 vault、不改其他 plugin。

### D-18｜2026-10-18｜定案｜Claude
**同步層做成可抽換介面（SyncAdapter）**，第一個實作是 Google Drive appDataFolder。日後若 Google 政策大變，可換成 Cloudflare D1、Firestore、Dropbox 等，不必重寫筆記功能。

### D-19｜2026-10-18｜暫定｜Claude
**PoC 測試頁放在 `quartz/static/personal-notes-poc/`**（發佈後在 `/static/personal-notes-poc/`），不連結、加 noindex，Phase 1 完成後移除。
理由：Google OAuth 只允許 HTTPS 或 localhost，iPhone 實機測試需要部署到 GitHub Pages 的 HTTPS 頁面。

### D-24｜2026-10-18｜定案｜Claude（依 PoC 結果）
**跨裝置同步輪詢間隔可以放寬。** changes.list 在伺服器寫入後約 3 秒即可看到（V-06）；03 §4.2 的「頁面可見時 3–10 分鐘輪詢＋開啟時先同步」足以讓使用者感受到即時，不需更密集的輪詢。

### D-25｜2026-10-18｜定案｜Claude（依 PoC 結果）
**`files.generateIds` 預先取得 ID 的建立方式確認可用。** 重複建立回 HTTP 409 `fileIdInUse`、不產生重複檔（V-07）。程式遇到 409 `fileIdInUse` 時視為「先前其實已建立成功」，改用 update。
另外：Drive `version` 每次寫入不是 +1（實測 1→3），程式不可依賴連號。appDataFolder 檔案有版本紀錄（V-08），可作為資料救回手段。

### D-26｜2026-10-18｜定案｜Claude（實作前自我審查）
**衝突判斷改用版本向量（vv），取代 `baseHlc`。** 原規則「`W.baseHlc >= V.hlc` 代表 W 看過 V」不成立：HLC 只保證排序，不代表因果；兩台裝置各自從同一舊版編輯時，後寫者的 base 時間可能大於另一台的版本時間，會把真正的同時修改誤判為「已取代」而默默丟掉一個版本。
vv 記錄每台裝置對該筆記的編輯次數，`V.vv ≤ X.vv` 才代表 X 看過 V。HLC 保留用於同時修改時決定顯示哪一版。詳見 03 §3.2、§4.4。

### D-27｜2026-10-18｜定案｜Claude
**MVP 的筆記內文以純文字顯示（保留換行），不渲染 Markdown。** 完全避免 XSS 風險、也不需要 DOMPurify 與 Markdown 函式庫，程式更小。Markdown 渲染移到 Phase 2（P2-6 一併處理）。內文仍以 Markdown 原文保存，日後可直接渲染與匯出。

### D-34｜2026-10-18｜定案｜Claude（依使用者實測回饋）
**未登入的人按下「用 Google 同步」之前，本站不連到 Google。** 原本每個章節頁一打開就預先載入 Google 登入元件（`accounts.google.com/gsi/client`），雖然沒有同步任何資料，仍是「未經同意就連到 Google」。改為：

無頭 Chrome 實測：未點擊前對 Google 帳號網域的請求 0 筆，點擊後 1 筆。
（網站本身的 Google Fonts 字型請求與筆記功能無關，不在此範圍。）

### D-36｜2026-10-18｜定案｜使用者（Claude 說明影響後選「修好並啟用」）
**啟用網站的 Service Worker（離線瀏覽）。** 原本 sw.js 放在 /static/，管不到整個網站，加上 GitHub Pages 無法送 Service-Worker-Allowed 標頭，上線以來註冊一直失敗。改為建置時另外輸出一份到網站根目錄並從那裡註冊。
- 策略維持「先網路、失敗才用快取」：有網路時永遠是最新內容；看過的頁面可以離線開啟。
- 只處理本站網址（Google 登入、雲端硬碟、搜尋 API 不經過）；個人筆記 config.json 不快取。
- 快取最多 400 筆；超過 3 MB 的檔案、3D 模型與影片不快取（沒有 Content-Length 時讀實際大小判斷）。
- 緊急撤回：sw.js 開頭註解有「自我移除」版本，已驗證部署後會移除 Service Worker 與快取。

### D-37｜2026-10-18｜定案｜Claude（Phase 2 C5、C6，取代 D-27 的純文字顯示）
**筆記內文改以 Markdown 顯示，用自寫的安全渲染器，不引入函式庫。**
- 支援：粗體、斜體、刪除線、行內程式碼、標題、清單、引用、分隔線、`[[條目]]`／`[[條目|顯示文字]]`、網址。
- 安全：全部用 DOM API 建立元素（不用 innerHTML）；只允許 `http(s)` 與站內連結，`javascript:` 等一律變純文字。解析（`ui/markdown.ts` 的 parse 函式）是純函式並有單元測試。
- `[[連結]]`：建置時輸出 `static/personal-notes/links.json`（標題、別名 → 網址），瀏覽器載入後解析；找不到的條目顯示為灰色（只在索引已載入時判斷，載入失敗不誤標）。輸入 `[[` 時跳出條目自動完成。
- 搜尋：多個關鍵字同時符合（AND）、`#標籤` 篩選、標籤一覽可點。

### D-38｜2026-10-18｜定案｜Claude（Phase 2 C2、C3）
**經節定位在瀏覽器端判斷；畫重點與書籤是獨立的功能模組。**
- 章節頁不改建置流程：前端在頁面載入後找出經文清單（`article > .markdown-preview-view` 內、第一條分隔線前的 `<ol>`），每一節加上 `data-v` 與 `id="v<節>"`。找不到就不顯示節點相關功能（章節格式改變時自動退回整章筆記）。
- 錨點保存節號＋引文（前後文、雜湊），日後經文排版變動時仍可用引文重新定位。
- `features/highlights/` 為第二個功能模組（紀錄 type `highlight`、`bookmark`），與筆記模組互不 import；選取文字後的「寫筆記」以 `COMPOSE_NOTE_EVENT`（document 上的自訂事件）交給筆記模組。
- 符合 11 的擴充方式：新增功能只需新資料夾＋在 `features/index.ts` 登記，同步、儲存、合併完全沒改。

### D-39｜2026-10-18｜定案｜Claude（Phase 2 C7，經 Codex 四輪審查）
**很久沒用的裝置分兩階段整理；雲端被清空時一律詢問使用者。**
- 第一階段：某台裝置所有檔案（含每天更新的登記檔）在雲端伺服器時間上超過 180 天沒有寫入 → 本機接手它的版本（只算本機保存的版本才算涵蓋；有並行版本就先不整理，等使用者在畫面上選）→ 確定上傳 → 寫下退役標記，不刪檔。
- 第二階段：最新的標記寫下滿 14 天、而且標記後舊 ID 沒有寫入 → 刪除它的檔案。標記後若又有寫入，等它再閒置 180 天時重新寫標記、從頭等。
- 被整理的裝置回來：看到標記（或自己的檔案消失且有標記）→ 換新裝置 ID，把本機資料重新上傳，不會誤判為「雲端被清空」。
- 其他裝置的檔案被移除時：有退役標記才由本機接手；原因不明則保留顯示、不自動傳回。
- 雲端完全清空（另一台按了「刪除全部」或資料被手動刪除）且本機有筆記：停止同步並詢問「重新上傳／清除這台裝置上的筆記／稍後再說」，不自動傳回也不自動丟掉。本機只剩已刪除紀錄時不打擾使用者。
- **殘餘風險（Drive 沒有「版本沒變才刪」）**：舊裝置若剛好在第二階段「重新列檔」與「刪除」之間的幾秒內寫入，那次寫入的雲端檔案會被刪掉；但資料仍在舊裝置本機，下次同步會因標記換新 ID 重新上傳。要遇到這種情況，必須是閒置半年以上、在等待期過後剛好那幾秒回來、且先前沒看到標記，機率極低。

### D-40｜2026-10-18｜定案｜使用者
**左上角的閱讀模式按鈕換成「我的筆記」入口；圖示列下方加文字按鈕「📝 我的筆記」。** 使用者實際使用後覺得閱讀模式（淡出側欄）沒有實質效果，改成通往〈我的筆記〉的入口，讓人比較直觀地找到。
