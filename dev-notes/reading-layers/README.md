# 分層閱讀（章節頁）

狀態：2026-11-22 定案，交 Gemini 實作（GOAL.md），主導者審查。

## 來源

讀者回饋（2026-11-20，iPad 讀出埃及記第 8 章）：本章整理的經文、註釋、整理者的話、原文混在一起；要一直往下滑；
iPad 看不到目錄；代號看不懂。主導者在正式站注入樣稿（`mockups/`），使用者看過後決定照主導者的建議做。

## 使用者決策（2026-11-22）

| 編號 | 決策 |
|---|---|
| R-1 | 先網站、再內容：網站先用通用規則改善舊格式（來源名稱說明卡、原文括號收成標籤、iPad 右欄）；筆記庫改用分層標記，逐章改寫（從創世記第 1 章開始）。 |
| R-2 | 頂端「經文｜研讀」兩個分頁，取代 Aa 面板的純經文切換；研讀頁的原文、背景、應用卡片預設收起。記住上次的選擇，第一次來先看經文。 |
| R-3 | 來源名稱：筆記庫正文把代號換成名稱（黃迦勒、拾穗、KingComments、BibleHub），網站做說明卡，另有「資料來源」頁。名單只維護一份：筆記庫 `_config/source_names.yaml`，同步到 `config/source-names.yaml`。 |
| R-4 | 整理者的話只做導覽（問題式小標、經文發生什麼、本章從哪走到哪）；解經或屬靈結論都要標出處，找不到就刪。 |
| R-5 | iPad 打開右欄時左欄自動收起。 |
| R-6 | 卡片三種：原文、背景、應用；看法不同的各家留在正文並列，不另做卡片。 |
| R-7 | **不做每章專用的設計**：所有介面由內容標記驅動，新書卷照標記寫就自動套用。 |

這幾條修正了先前的 U-10（內容來源層次延後）與 U-23（純經文只在 Aa 面板）：現在格式已穩定，改由分頁取代。

## 以後新書卷要做什麼

通常什麼都不用做：筆記庫的新章節照分層標記寫（閘門 `util/check_layers.py` 會擋），同步上站就有這些介面。
唯一要注意的是新的註釋書名：筆記庫的閘門會警告沒登記的書名，補進 `_config/source_names.yaml`，下次同步就會出現在說明卡。
