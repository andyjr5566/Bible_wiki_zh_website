## 為什麼要做

讀者回饋（2026-11-20，用 iPad 橫放讀出埃及記第 8 章）：本章整理資訊很豐富，但經文、註釋、整理者自己的話、

iPad 上看不到目錄；「CT」「KC」這些代號看不懂。

使用者決定（2026-11-22）：內容端（Obsidian 筆記庫）改寫法、用固定的標記把層次標出來；網站端用**通用元件**
把這些標記呈現出來。**不做任何「某一章專用」的設計**：所有功能都必須對任何章節頁自動生效，
以後新寫的書卷章節只要照標記寫，同步上站就自動有這些介面。

樣稿（主導者在正式站上注入畫出來的，只是示意）：`dev-notes/reading-layers/mockups/`。

## 內容契約（筆記庫產生的 markdown 會長這樣；你只讀不寫）

本章整理（`## 本章整理` 之後）採用下列標記。舊章節要逐步改寫，所以**新舊兩種格式都會在站上同時存在很久**：
新格式要呈現得好，舊格式不能壞，並且盡量用備援規則改善（見 B 階段）。

1. **來源名稱**：正文不再寫代號，寫人看得懂的名稱：黃迦勒、拾穗、KingComments、BibleHub、STEP Bible；
   拾穗收錄的各家寫書名或作者（《丁道爾》、《精讀本》、丁良才……）。完整清單、全名、說明與比對用的正規式在
   `config/source-names.yaml`（由筆記庫 `_config/source_names.yaml` 同步過來，**唯一真相，不要在程式裡另寫一份名單**）。
   舊章節還有 CT／GT／KC／BH 代號：CT＝黃迦勒、GT＝拾穗、KC＝KingComments、BH＝BibleHub（同一份 yaml 的 `code` 欄位）。
2. **經文原句**：「」裡是和合本原句、後面**緊接**經節括號時，就是經文：
   `「起初，神創造天地」（1節）`、`「他說有，就有，命立，就立」（詩33:9）`、`（11-12節）`、`（第27節）`。
   括號裡可以是連結（`（[[詩篇33篇神話語創造|詩33:9]]）`，渲染後是 `（<a>詩33:9</a>）`），括號裡經節之後可能還有 `；另見…`。
   同章的「N節」指本章第 N 節；他卷用書卷簡稱（簡稱表在 `config/bible-books.json` 的 `short`）。
   沒有緊接經節括號的「」是註釋或其他來源的逐字引句。『』是重點詞，不是引句。
3. **分層卡片**（Obsidian callout，`-` 代表預設收起）：
   - `> [!original]- 標題`：原文——希伯來／希臘字、音譯、Strong 編號、字典的意思。
   - `> [!background]- 標題`：背景——歷史、地理、文化、古代近東對照等經文以外的背景資料。
   - `> [!application]- 標題`：應用——屬靈應用、靈意與預表的讀法。
   Quartz 會把它們渲染成 `div.callout[data-callout="original|background|application"][data-callout-fold]`。
   卡片標題只寫主題，類別（原文／背景／應用）由你的樣式顯示。舊章節還有 `[!note]` `[!important]` `[!question]`
   `[!example]` 等一般 callout，照現在的樣子呈現即可。
4. **小標**：小節是 `###`，小節裡讀者會問的問題用 `####`（例如「#### 「起初」是什麼時候？」）。
5. 希伯來／希臘字母與 Strong 編號（H1254A、G3056）在新格式只會出現在 `[!original]` 卡片裡；
   舊格式散在句子裡，常寫成 `（בָּרָא，H1254A）`，Strong 編號已經被包成 `span.strong-no`。

範例檔（主導者已從筆記庫複製進來，你不需要也不要去讀寫筆記庫）：`test_content/01 創世記/第1章.md` 是第一個
新格式的章節；`test_content/02 出埃及記/第8章.md` 是舊格式。`config/source-names.yaml` 也已放好。

## 使用者已定案的介面（照做，不要改方向；有更好的細節做法可以提，寫在回報裡）

1. **頂端「經文｜研讀」分頁**（取代 Aa 面板裡的「研讀｜純經文」切換）
   - 經文頁只有經文（沿用現在純經文模式藏的範圍：知識節點、本章整理、附錄藏起來）；研讀頁藏經文清單與朗讀列，
     直接從本章知識節點、本章整理開始，不用往下滑。
   - 記住讀者上次選的（localStorage，全站共用一個值）；第一次來的人先看經文。
   - 桌機、平板放在章節標題下方，捲動時黏在頂端；手機放進現有的章節快捷列，取代原本的「本章整理」連結。
   - 點研讀頁裡的經節小標籤（見 3）→ 切到經文頁、捲到那一節並短暫標示（沿用 verse-return 的標示樣式）。
   - 「↩ 回到剛才的經節」（verse-return）、朗讀、個人筆記、畫重點、互動網站提示都要照常運作；
     純經文模式原本處理的「點到指向被藏內容的連結時暫時顯示那一段」也要保留在新分頁上。
   - Aa 面板拿掉「研讀｜純經文」那一列（其他設定不動）。
2. **本章導覽面板**（可收起）
   - 內容：①怎麼看這一頁（小圖例：褐色字＝聖經原句；虛線名字＝點了看是哪本註釋；原文／背景／應用卡片想深入再點開）；
     ②本章目錄（研讀頁列本章整理的 `###`／`####`，經文頁列本章整理第一個小節表格或「經文大綱」的段落，
     沒有就列 `###` 標題的經節範圍；目前讀到的那一項標亮）；③本章引用的資料（本頁實際出現的來源，
     用 yaml 的 name＋title＋note）；④相關資源（本章知識節點數、附錄地圖、互動網站、「全部資料來源說明 →」連到 `資料來源` 頁）。
   - 平板（800–1200px）：右側抽屜，打開時左欄自動收起、正文讓出位置，不可蓋住正文；收起後只留一個小按鈕。
   - 桌機（>1200px）：放在右欄，取代現在的目錄（table-of-contents），關係圖留在它下面。
   - 手機（<800px）：快捷列加「目錄」按鈕，打開成底部抽屜。
   - 圖例只在研讀頁出現。
3. **正文呈現**（建置時處理，不要等瀏覽器跑完才閃一下）
   - 經文原句（契約 2）：「」連同引號用深褐色，後面的經節括號變成小標籤（例：`1節` `詩33:9`），點了照 1 的規則跳。
   - 來源名稱：正文出現 yaml 裡的名稱（含舊代號）時，加點狀底線，點／觸碰打開說明卡：
     名稱、全名、說明、「本章原文網頁 ↗」（從本頁參考資料裡找對應網址，用 yaml 的 `url_hint` 比對；拾穗收錄的各家用拾穗的網址）、
     「全部資料來源 →」。舊代號（CT 等）的卡片標題寫「CT＝黃迦勒」，讓讀者看懂代號。
     不要在標題、連結文字、表格標頭、程式碼、mermaid 裡加。
   - 分層卡片：三種卡片各一個顏色與標籤（原文＝藍綠、背景＝土黃、應用＝綠，要配得上羊皮紙與紫色的整站風格，
     深色模式也要好看），收起時一行：標籤＋標題＋第一句的開頭當摘要；展開顯示全文。原文卡片展開時底部自動加一行
     「出處：STEP Bible（CC BY 4.0）」。
   - 備援（舊格式）：句子裡的 `（希伯來字…，H1234）` 這種括號收成一個「原文」小標籤，點了在旁邊出現小卡顯示原本的內容；
     新格式卡片裡的不要收。
4. **資料來源頁**：筆記庫會產生 `資料來源.md`（網站同步後就有），面板與說明卡連到它；同步腳本要把它加進同步清單。

## 工程規則

- 先讀 `dev-notes/ux-improvements/README.md` 的〈共通規則〉與〈使用者決策〉（U-4 連結樣式、U-23 純經文、U-24 互動網站提示等），
  不得破壞既有功能。這次的決策記在 `dev-notes/reading-layers/README.md`。
- 分支：從 main 建 `feature/reading-layers`，在本地工作。**不要 commit、不要 push**（主導者審查後提交）。
- 可改的地方：`quartz/`、`plugins/<本地外掛>`、`quartz.config.yaml`、`config/`、`.github/`、`sync_content.ps1`、`scripts/`、
  `test_content/`、`dev-notes/reading-layers/`。**不可改**：`content/`（會被同步蓋掉）、`.quartz/`（CI 重新 clone）、
  `C:\Obsidian\Hermes`（筆記庫，只讀）。新增本地外掛要同時改 `quartz.config.yaml` 與 `.github/scripts/prepare-plugins.sh` 的 `LOCAL_PLUGINS`。
- 優先擴充既有模組：`plugins/site-ux`（Aa 面板、純經文：`lib/pureMode.ts`、`lib/readingView.ts`）、`quartz/util/chapterRegions.ts`／`chapterDom.ts`、
  `plugins/verse-return`、`plugins/read-aloud`。判斷規則寫成可測的純函式並附單元測試（照〈共通規則〉第 7 條），
  DOM 放在薄薄的外層。共用的值只定義一次。中文註解寫「為什麼」。
- 建置與測試一律在 PowerShell 跑（Bash 會被應用程式控制擋住原生模組）：
  `npx quartz build -d test_content -o <你的暫存目錄>`；完整內容建置約 8 分鐘，只在最後驗收時跑一次。
- 公開文字規則：讀者看得到的每個字都不能有內部話（檔名、欄位名、json、yaml、「資料尚未加入」、slug、callout 這類詞）。
  沒有資料就不顯示那一區。說明卡、圖例、按鈕的文字用一般人看得懂的白話。
- 無障礙：按鈕要有可讀名稱、可用鍵盤操作、說明卡可用 Esc 關閉、對比 ≥ 4.5:1（淺色與深色都量）；
  SPA 換頁後所有功能要重新綁定（照 knowledgeNodes 的 AbortController 做法）。
- 不要用 `scrollIntoView` 捲整頁去對齊小元素（使用者討厭頁面自己亂捲）；跳到經節時只捲一次、捲到那一節。

## 分階段計畫（一次一個階段）

- **A. 建置時的正文處理**：讀 `config/source-names.yaml`；經文原句、來源名稱、三種卡片的樣式與摘要、舊格式原文括號標籤；
  說明卡與原文小卡的腳本。測試資料放進 test_content。交件附桌機 1440、平板 1180×820、手機 390 的淺色／深色截圖
  （創世記第1章、出埃及記第8章各幾張），以及單元測試結果。
- **B. 經文｜研讀分頁**：取代純經文切換，含記憶、手機快捷列、經節標籤跳轉、和 verse-return／朗讀／筆記的相容。
  附 e2e 檢查腳本（參考 `plugins/site-ux/e2e/purecheck.mjs`）與截圖。
- **C. 本章導覽面板**：三種寬度的版面、圖例、目錄標亮、引用資料、相關資源、收起狀態。附 e2e 與截圖。
- **D. 收尾**：同步腳本（複製 `_config/source_names.yaml`→`config/source-names.yaml`、把 `資料來源.md` 加進同步清單）、
  部署檢查（yaml 讀不到或格式錯時建置失敗並說明）、無障礙與對比實測、深色模式、完整內容建置一次、
  更新 `dev-notes/reading-layers/README.md` 的進度與維護說明（以後新書卷要做什麼：通常什麼都不用做；出現新的註釋書名時補 yaml）。

## 完工定義

- 任何章節頁（新格式、舊格式、沒有本章整理的頁）都正常；條目頁、首頁、互動網站總入口不受影響。
- 單元測試全過；既有 e2e（smoke、purecheck 要改成新分頁的版本、verse-return、read-aloud、book-picker、interactive-check）不回歸。
- 三種寬度、淺深色截圖都看過；對比實測數字寫進回報。
- 沒有任何一行程式寫死某一章、某一卷或某個來源名稱（名單只在 yaml）。
