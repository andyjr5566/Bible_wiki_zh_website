## 0. 一句話目標

在第八日之後接上最後一章「**七的節奏**」，像漩渦一圈圈往外：
安息日 → 七個七天 → 第七個月 → 第七年（安息年、豁免年）→ 七個七年 → 禧年，
最後回到開場的夜空，首尾相接。

同一批：
- 安息年與禧年的回聲拍；
- 首頁入口卡；
- 和律法地圖互相連結；
- 修兩個已知小缺點。

完成後 commit、回報，然後**停下來**。部署由使用者自己處理，不在本批範圍。

## 2. 分工（省 token 是硬要求）

模型：Sonnet 5.5 與 Haiku 5.5，effort 都是 high。定義在 repo 根目錄 `.claude/agents/`：
- `jf-engineer`：Sonnet，工程；
- `jf-collector`：Haiku，蒐集與跑檢查。

| 誰 | 做什麼 | 不做什麼 |
|---|---|---|
| **主筆 Opus** | 研經內容（`data/*.yaml` 的文字、原文說明、章末 note、條目簡介）；SPEC.md 本批分鏡；契約檔；看總覽圖驗收、抽查；Codex 提交與裁決；commit；回報 | 不寫場景／介面程式（一兩行的整合小修例外）；不自己跑長時間的檢查腳本；不逐張看截圖；不重讀讀過的檔 |
| **Sonnet `jf-engineer`** | 新場景（漩渦、各圈、回聲拍場景）、介面、資料腳本與建置檢查、律法地圖與首頁的連結、兩個小缺點、靜態插圖、錄影 | 不寫研經文字；不 commit |
| **Haiku `jf-collector`** | raw 索引（先擴充 `build_index.py` 的書卷對照）；條目名稱確認與定義抽取；跑 `check-*`、`shoot-*`、`record.mjs`、file:// 並回報數字 | 不判斷、不寫內容。回報要附**狀態文字原文**與數字，不能只寫「無錯誤」；主筆抽查 |
| **Codex（唯讀）** | 本批內容審查，最多 2 輪；每輪後主筆跑 `git status util/` | 不寫任何檔 |

**省 token 守則**（沿用 GOAL-2，加上這兩批學到的）：
1. 委派訊息只寫：任務、檔案範圍、要讀的 SPEC 段落、驗收條件。不貼整份規格。
2. 修改一律 `SendMessage` 續用同一個代理；代理撞到用量上限停下時，主筆先看 `git status` 確認它做到哪，再決定續派或自己收尾。
3. 長時間的檢查（全站 idle-motion、全站錄影、四組截圖）交給 Haiku 在背景跑；主筆只看它回報的數字與 ffmpeg 拼好的總覽圖。單拍重測用 `check-idle-motion.mjs --only=cue`。
4. 讀 raw 用 `Read` 的 offset／limit，只讀索引指到的段落；GT 只用本段有標記的段落。
5. Codex 自己讀 raw；主筆只給範圍與規則（照 `tools/codex-review-5.md` 的格式）。

**這兩批踩過的坑（委派時寫進驗收條件）**：
- 鏡頭在兩個 cue 之間是直線移動，會穿過羊群、會幕側牆。新 cue 的鏡頭要看前後 cue 的位置；錄影後用 `ffmpeg select='gt(scene,0.4)'` 掃，每個候選拼成 contact sheet 確認是設計的轉場，不是穿模或硬切。
- 會隨「目前拍」出現的 fixed 元素，會疊到前一拍還沒離開的說明框。新 UI 要嘛掛在自己的說明框上，要嘛做逐步捲動的重疊量測（1440／1024／820）。
- 新 CSS class 先 grep 舊樣式有沒有同名（`jf-fold` 撞過）；一律加功能前綴。
- PowerShell 的 `[IO.File]` 吃的是 .NET 的工作目錄，跟 `Set-Location` 不同步：一律用絕對路徑。檔案多為 LF，`Replace` 前先確認換行。
- 寫 commit 訊息用 Write 工具寫進 scratchpad，再 `git commit -F`；PowerShell 的 `Set-Content -Encoding utf8` 會加 BOM。
- 手機說明框約佔畫面下 2/3，主角要落在標題列和說明框之間那一條；`check-idle-motion` 手機版偏低時，先截圖看主角是不是躲在框後面。

## 3. 本批範圍

### 3a. 七的節奏（新章，接在住棚節／第八日之後）

| 圈 | 經文（開工先確認節數） | 畫面與互動 | 注意 |
|---|---|---|---|
| 安息日 | 利23:3、出20:8-11、創2:2-3 | 漩渦中心：一天一天點亮，第七天停下 | 理由照經文：出20:11 |
| 七個七天 | 利23:15-16 | 回看七七節的 7×7 數算，跳回 `count` 拍 | 不重做互動，連回去 |
| 第七個月 | 利23:24-36 | 一圈裡點出七月的三個節期 | 只指回秋季三章 |
| 第七年 | 利25:1-7、出23:10-11、申15:1-2／12、申31:10-13 | 田地休耕、債與奴僕的豁免；住棚節宣讀律法（住棚節章末已有連結，這裡接上） | 安息年與豁免年分開講，照經文 |
| 七個七年 | 利25:8 | 漩渦擴到 49 | 數字由建置檢查從經文解析 |
| 禧年 | 利25:9-13 | 贖罪日吹角、宣告自由、各歸本家；**沿用 blow 長按互動** | 利25:9 的吹角與用字先查 STEP（和利23:24 不同字的教訓） |
| 回到夜空 | 無新經文 | 漩渦收回開場的月相夜空，首尾相接 | 無字或只有一句 |

- 回聲拍候選（主筆讀完經文與註釋定案，2–3 拍）：耶34:8-17（立約放奴僕又反悔）、代下36:20-21（地享受安息，連到利26:34-35）、尼10:31（第七年不耕種、豁免債）。
- 章末「舊約其他書卷」照第二批的寫法：每條交代讀者看什麼（跟律法的對照、經文給的原因、原文同不同字），120 字內；沒有資料的小節不顯示。新約連結只放知識庫裡已有的條目。
- 建置檢查：七的倍數（7、49、第 50 年）從經文解析，有期望值測試與反例測試。
- raw 索引要補：`leviticus 25`、`leviticus 26`、`deuteronomy 15`、`deuteronomy 31`、`exodus 20`、`exodus 23`、`genesis 2`、`jeremiah 34`、`2_chronicles 36`、`nehemiah 10`。四家＋STEP 都齊（2026-10-10 確認）。

### 3b. 律法地圖互連

- 節期網站每章章末加「律法地圖」小節，列出該章經文對應的地圖條文（名稱＋一句＋另開連結，照 `web-link-out-dont-copy-kb` 的做法）。
- 律法地圖（`appendix/website/摩西五經/律法地圖/`）的節期相關條文加「在節期網站看這一段」，連到對應章的錨點。
- 工程代理先列出對照表（地圖條文 id ↔ 節期章 id），主筆確認後才實作；連結要能在 file:// 與部署後的相對路徑都通。

### 3c. 首頁入口卡

- `appendix/website/index.md`（由 `build.py` 產生）加一張「耶和華的節期」卡，樣式沿用既有入口卡；卡上的一句說明由主筆寫。

### 3d. 兩個小缺點

1. 說明框收起時，場景的左右推移（`poses2.ts` 的 DX2／UP2、第一批的同類表）要平順歸零；展開時再回來。
2. 手機逐拍檢查主角和說明框的重疊：工程代理寫一支量測工具（主角包圍框 vs 說明框），列出重疊的拍，逐拍調手機鏡頭。
